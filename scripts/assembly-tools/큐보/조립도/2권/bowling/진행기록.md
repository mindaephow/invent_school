- 발사 = 장전 → 바퀴 올리기 → 내리기 → 팔이 12° 들려 바퀴가 풀려 구르고 팔은 중력으로 0° 로 내려옴. 팔 각도 도/라디안 혼동 버그 고침(`armTo`). 지렛대: 레인이 관절 둘레로 기운다(바퀴가 위쪽이면 `올렸을 때` 기본 20°, 아래 끝이면 `굴러간 최종` 0°), 레인 아래 끝은 바닥에서 멈춤, 바퀴 올라가는 한계 −55mm.
- 추정·미확인: 팔이 바퀴에 닿는 각도(15° + 위로 갈수록 0.5°/mm), 발사 12° 들림, 지렛대 방향·크기, 2번 쪽 동작은 눈으로 다 확인하지 못함.

## 함정
- 일부만 보이는 판(모터·벽에 가려 칸1~5 안 보임)의 holefit 격자는 한 칸 밀려 매겨질 수 있다(18·19·34번). 그 판 위의 확정된 3D 점(모터 몸 특징점 등)을 격자 카메라로 투영해 오차를 보고(밀림 0 → 12~14px, ±1 → 56px 이상) 칸 번호를 고친 뒤 링 칸을 읽는다. 링을 하나의 띄움 높이로 투영해 모이면 칸 읽기가 맞다는 독립 확인.
- 3단블록은 돌기 면(±z)과 큰 구멍 면(±y)이 직각이다 — 책 한 장의 실루엣으로 면을 정하지 말고 뒤 번호(20번)에서 같은 면에 있어야 하는 돌기들로 확정.
- 리벳이 브라켓 안에 꽂힌 채 떠 있는 책 모양이면 리벳·브라켓 띄움을 같게(10·13번 75). 책 글('긴 쪽'·'※ 리벳 홈 방향 주의'·번호 말풍선)은 번호 시작 때 먼저 읽는다(사용자 지적).
- holefit 가 가려진 판에서 기준에 걸리면: 보이는 두 변의 연장선 교점으로 숨은 모서리를 구하고(6번), 보정 격자에서 리벳 끝이 정수 칸으로 떨어지는지 확인한 뒤 `infer_grid --anchor`(구멍 조각은 `--제외` 다각형으로 뺌).
- 그림 DB 업로드: `public/_refs_tmp/bowling` 에 index.json+그림 복사 → `refStore.save('cubo-2-bowling', 번호, idx, dataURL, note)` → 폴더 삭제.

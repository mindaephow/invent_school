## 함정 (같은 실수 방지)
- 책이 '뒤집기'라 쓰면 먼저 뒤집은 모델부터 만들어 책과 비교한다 — "그대로 본 것"이라고 마음대로 읽지 않는다(15번에서 몇 시간 소모). 가설을 모델로 만들어 판 카메라로 투영 → 링과 거리(`05_조립.md` 5-7절)가 가장 빨랐다. 도구(`frame_fit`)가 `15_axes.json` 을 덮어쓰니 쓴 뒤 `axes_fit`+`rotate_to` 로 되돌린다.
- 부품 폭(구멍 수)은 가까운 쪽 구멍 간격으로 센다(다른 판 간격으로 나누지 않는다).
- `observe.py add` 로 같은 번호를 다시 기록하면 이미지 파일 번호가 어긋나 결합 기록이 6방향 그림을 가리킨다 → 고칠 땐 `hammerbattle_obs.json` 에서 그 번호를 지우고(pop) 처음부터 다시 add.
- 앞 번호 부품을 뒤 번호 코드에서 고치면(8번 copy 자세) 앞 번호(6)의 증거 지문이 바뀌어 빌드가 막힌다 → 그 번호 record_check 다시. 앞 번호가 바뀌면 그 번호가 마지막이 되게 `HB_UPTO=번호` 로 빌드해 화면 데이터를 새로 쓴 뒤 캡처. 뒤 번호가 골격이면 증거 있는 번호가 막힌다(9·10번 증거 다시, 11~14 증거는 잠시 빼 뒀다 되살림).
- 새 창고 부품이 숨은 몸과 겹치면 우연한 맞물림 검사에 걸린다 — 어긋남 (2.5,0,2.5) 만 통과. 새 창고 어긋남은 `HB_O11` 같은 환경변수로 여러 값 시험.
- 9번은 처음에 프레임을 눕혀 읽어 카메라가 올려다보는 거울 해만 나왔다 → 10·13번 책에서 정정. 한 번호로 방향이 안 정해지면 뒤 번호 책을 읽는다.
- 표에 줄 없는 부품(작은기어·큰기어·중간바퀴·135도 프레임·515프레임)은 기본 규격(connectors)으로 유추해 놓았다.

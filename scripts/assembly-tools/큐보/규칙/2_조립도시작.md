# ② 조립도 시작 — 새 조립도마다 한 번

- 새 조립도를 시작할 때 이 문서를 위에서부터 한 번 따라간다. 끝나면 번호마다 `3_번호하나.md` 로 간다.
- 순서: **0 시작 환경 → 01 번호 등록 → 02 이미지 자르기 → 03 부품 정리 → 04 창고 정리 → 05 번호별 조립(③)**. 앞 과정이 끝나기 전에는 다음으로 가지 않는다(`number_start.py` 가 02·03·04 미완을 막는다).
- 03·04 는 "1차"다 — 모든 번호가 적혀 합계 = LIST 이면 끝이고, 조립 중 어긋난 것을 발견하면 그때 표를 고치고 이어간다.
- 규칙 번호(A2·P3 …)는 도구 메시지가 가리키는 번호라 그대로 둔다. G·K 번호는 `5_부품사전.md`, 그 밖의 번호는 규칙집 `큐보 부품결합규칙.md`.

## 0. 시작 환경 (00)

- **새 차시의 기본 환경은 `new_assembly.py` 가 갖춘다:** `Asm(..., guideMode="mates")`(G26), `_rules.json` 의 `parts_sum`·`mate_marks`·`strict`·`orient_check`·`placecheck`·`img_db`·`rulecheck` 전부 켬, 카메라 보는 중심은 뷰어 `fitCenter`(E11).
  - 검사·환경은 번호마다 손으로 챙기지 않는다. 빠진 항목이 보이면 번호가 아니라 `new_assembly.py`·도구를 고친다(C8).
- **00-1 [도구:release_start.py — `handoff.py <이름> --아이디 <계정> --시작` 과 `number_start.py` 가 부른다] 조립도 작업에 들어갈 때는 막는 것을 전부 풀고, 새 규칙으로 처음부터 다시 확인한다.**
  - ① 📷 카메라(`ivs_assembly_cams`)·❄ 모습 기록(`ivs_assembly_poses`)·✓ 완료 표시(`ivs_assembly_status`)를 백업(`refs/<이름>/_release_backup/<시각>.json`)하고 모두 푼다. 보기만은 `--보기`. 시작할 때 한 번만 돈다(도중에 다시 돌리면 새로 저장한 값이 지워진다).
  - ② 조립 스크립트의 손값 — 손 좌표(`place`·`_abs_place`·`Part(...)` 직접 생성의 위치, `p=`, 안내점, `side=`, `shift=`)와 **띄움·두께 숫자(`hover=`·`thick=`·`pegDepth=`·`settleHover=`, `hover=0.01` 은 규칙 G19 라 둔다)** — 숫자만 적은 것과 `ZL - 8.0` 처럼 숫자가 섞인 식 모두 `handcheck.py` 가 센다)는 `strip_hand.py` 가 `refs/<이름>/_script_backup/` 에 백업한 뒤 지운다. 위치 숫자는 원점 `(0, 0, 0)` 으로 돌아가므로 부품이 원점에 겹쳐 보이는 것이 정상이고, 번호를 만들 때 `attach`/`recv` 로 다시 놓는다(복원: `python strip_hand.py <이름> --복원 <백업>`).
  - ③ **[도구:number_start → convert_hole_ids.py] 옛 구멍 번호(`hN_M`)는 차시를 시작할 때 자동으로 바꾼다.** 스크립트를 백업하고 같은 위치의 부품 DB 번호로 바꾼다. 도구가 못 정한 줄은 `number_start` 가 줄 번호와 함께 알려 주니 그 줄만 손으로 바꾼다(같은 구멍 찾기: `pegprobe`·`get_part_connectors`).
  - ④ `number_start.py <이름> 1` 이 ❌(02 이미지·03 합계·04 창고)로 막으면 그 자리에서 B9 로 풀고 1번에 들어간다. 숫자를 맞추려고 고치지 않고 원인을 고친다(관리자 확정 수량은 `qtyOverride`, A2).
  - ⑤ 풀기 전 기록·푼 번호·고친 원인은 마지막 보고에 적는다. 작업 도중 사용자가 새로 저장한 ❄/📷/✓ 는 B3 대로 우선한다.

## 01 번호 등록

- **A15 [문장] 번호 표(01): 교재 번호 그대로가 조립도 단계다.** 맨 앞 완성품 사진 = 0, 마지막 "완성" 그림 = 99 이고 둘 다 단계로 만들지 않는다("완성" 화면은 자동으로 붙는다). 쪽마다 어떤 번호가 있는지 왼쪽→오른쪽·위→아래로 훑어 적고, 헷갈리면 앞·뒤 쪽과 완성품 사진을 같이 본다. 눈대중으로 잡은 것은 "추정". 차시 제목 글자(띄어쓰기 포함)는 조립도 `chapter` 와 똑같이 쓴다.
- **A16 [도구:build] 번호만 등록한 뼈대 단계(01)의 설명은 "(작성 전)" 으로 쓴다 — "(채우는 중)" 은 빌드가 막는다.** 스크립트 끝(`A.save_links()` 앞)에 `stepchecks.apply(A, "<이름>")` 가 없으면 `build.py --write` 가 거부한다. 뼈대 상태로는 푸시하지 않는다.

앞·뒤·위는 3D 완성 화면에서 기준 부품(센서·메인보드·바퀴)의 위치로 확인하고, 확인이 안 되면 "추정"으로 표시한 채 멈추지 않는다(사용자 확인은 마지막 보고) ③ `refs/<이름>/00_1.jpg` 로 저장하고 `index.json` 에 `{"step": 0, "idx": 1, "file": "00_1.jpg", "note": "완성품 방향선 — …"}` 를 넣는다 ④ 3번과 같은 방법으로 `__ivsRefsUpload('<이름>', 'cubo-<권>-<이름>', [0])` — 임시 폴더에는 새 그림 1장만 두고 올린 뒤 지운다 ⑤ "🖼 완성 사진"에서 두 그림이 세트로 보이는지 확인한다.

## 03 부품 정리 (1차)

- **A2 [도구:number_start·build, `parts_sum`] 03 부품 정리(1차): 모든 번호의 사용 부품을 책 그림에서 읽어 번호별 표(`USED`)로 적고 교재 LIST 와 합계를 맞춘다.**
  - "N~M번 2개 만들기"는 2배로 센다. 합이 안 맞으면 숫자를 고치지 말고 그림을 다시 보고 어느 번호를 잘못 읽었는지 찾는다. 안 맞는 부품이 남아 있으면 번호 작업을 시작하지 않는다.
  - 번호 설명(note)의 아래 줄에 `▣ 사용 부품: 부품 개수, …` 를 한 줄로 적는다. 합치는 단계는 "▣ 사용 부품: 없음(합치는 단계)", 2개 만들기 범위의 첫 번호는 끝에 "(N~M번 2개 만들기)", 나머지 번호는 "(2벌)". 스크립트에는 번호 → 부품 표 `USED` 를 두고 반복문으로 붙인다(P3).
  - 리벳은 그림 옆 "(n)" 숫자 그대로, 다른 부품은 그림에서 센 값(근거가 약하면 "추정" — 코드 주석과 보고에만 적고 note 에는 쓰지 않는다).
  - 부품 이름은 `<이름>_list.json` 의 이름과 똑같이 쓴다(LIST 이름과 DB 이름이 다르면 LIST 이름).
  - 교재 LIST 가 책과 실제로 다르다고 관리자가 확정한 수량은 `Asm(..., qtyOverride={"15프레임": 6})` 로 적는다. 합계 대조는 모두 `asmpath.list_counts()`(LIST + 확정 수량)를 쓰고, 화면은 그 개수를 기준으로 보이며 책 개수는 "⚠ (책 N개)"로 알린다.
  - 3D 모델이 없는 부품은 번호 설명에만 적고 모델 부품 수에 넣지 않는다. 그런 부품만 나오는 번호는 빈 단계로 두고 `USED` 에 "고무밴드 2 (3D 모델 없음)" 처럼 적는다(줄은 `bands`, G10).
  - 03 을 끝내면 번호별 부품 표 / LIST 와 맞는 부품 / 안 맞는 부품과 의심 번호로 보고한다.
- **A2a [도구:build, 화면 배지] 03 은 "1차"다 — 책을 번호 순서대로 훑어 모든 번호의 사용 부품을 적는 것이고 완벽할 필요가 없다.** 모든 번호에 `▣ 사용 부품` 이 있고 부품별 합계가 LIST 와 같을 때 `build.py --write` 가 배지를 "1차 완료"로 적는다(`prepDone.parts`). 조립하다 틀린 것을 발견하면 표를 고치고 이어간다.

## 04 창고 정리 (1차)

- **A3 [문장+도구:build·violations `store`] 04 창고 정리(1차): 책을 번호 순서로 보며 번호마다 slot·history 를 정한다.**
  - ① 연달아 이어지는 번호(세트, "N~M 2개 만들기")는 같은 창고 ② 새 세트가 나오고 기존 세트가 안 보이면 새 창고 ③ "N + M" 합치기는 앞(작은 번호) 창고로 가져가 조립.
  - 창고 0 = 메인, 1~5 = 따로 만드는 자리이고 **1번은 창고 1에서 시작한다.** 창고가 바뀌면 `history` 글, 안 보여야 할 앞 번호는 `hideMade`.
  - **그룹 이름:** "그룹 1, 그룹 2…"(원점에 가까운 쪽이 먼저, 그다음 왼쪽부터)로 쓰고 다른 이름으로 바꾸지 않는다.
  - **history 쓰기:** 창고·불러오기는 번호·설명 본문에 쓰지 않고 `history` 에만 쓴다(예: "창고 1에서 불러와서 조립 → 그룹 1").
  - **둘째 벌 복사 [도구:violations `store` ▣ — 화면 창고 칩]:** "N~M번 2개 만들기"는 한 벌만 만들고, 둘째 벌은 그 범위의 마지막 번호에서 `copy_to_slot(묶음, 다른 창고, 이름, until=쓰는 번호)` 으로 복사해 보관한다. 같은 번호에 둘째 벌을 새로 만들어 나란히 놓지 않는다(같은 창고 옆에 두면 겹친다). 예외: 책 그림에 두 벌이 함께 그려져 있으면 그 번호에서 둘 다 책 자리대로 만든다(거울쌍은 거울 자세로 결합, F9 — dropchecker 27번).
    - 복사본은 `until` 전까지 보관 중(화면에 안 보임)이고 원본과 기본 z +300 떨어져 있으며 읽기 표 부품 수에서는 빠진다(`copyOf`).
    - 거울로 놓는 둘째 벌(대칭 조립, F9)은 복사가 아니라 거울 자세로 따로 놓는다.
  - **사용자 ✓:** 앞 번호에 사용자 ✓ 가 있으면 그 번호의 부품 데이터는 고치지 않고 새 번호에서 `hideMade` 로 숨긴다.
- **A3a [도구:build 배지·hidecheck.py·violations `store`] 04 도 "1차"다 — 배지는 기록이 있다는 뜻일 뿐 정리가 맞다는 증거가 아니다.**
  - 모든 번호에 slot 이 있고 창고가 바뀌는 번호마다 `history` 가 있으면 배지가 "1차 완료"(`prepDone.slots`)다.
  - 번호마다 작업장(화면)을 책과 비교한다. 책에 없는 앞 번호 부품이 같이 보이거나 놓인 자리·창고가 책과 다르면, 증거를 남기기 전에 그 자리에서 `hideMade`·slot·`history` 를 고치고 다시 불러와 확인한다(A5).
  - **`hideMade` 는 번호마다 그 번호 책 그림에 나오는 부품만 남기게 정한다.** 앞 번호 줄을 복사해 붙이지 않는다. 새 창고(slot 이 바뀌는 번호)는 그 창고에 속하지 않는 앞 번호(이미 다른 창고로 합쳐 간 번호 포함)를 모두 숨긴다. 합쳐지기를 기다리는 부품은 "만든번호:부품순서" 키로 숨기되 값은 `side.until` 에서 계산해 만든다.
  - `python hidecheck.py <이름>` 이 다른 창고 부품이 보이는 곳을 찾지만, 합쳐 간 같은 slot 번호는 못 잡으므로 최종 판단은 책 그림이다.
  - 화면 반영이 `build --write` 에 막히면 막은 항목을 B9 순서로 풀어 반영하고, 반영 전에는 그 번호를 "책과 같다"고 증거로 적지 않는다.
  - **반영 막힘 푸는 법:**
    - ① 새 창고의 첫 부품과 옆자리 묶음이 앞 몸체 자리와 겹쳐도 `noGuide` 를 붙이지 않는다 — 점검기는 같은 창고(slot)의 부품끼리만 결합으로 센다(G1b).
    - ② 옆자리 묶음이 바닥(y=0) 아래로 내려가면 `side_row(..., floor=True)`.
    - ③ 합치는 부품의 안내점이 없으면 `to_side(..., hosts=(받는 부품…))`.
    - ④ 긴 축은 돌기 가운데가 구멍에서 멀어 `marks='auto'` 가 못 내므로(`join_marks` 3.5mm 한계) 받는 구멍 입구를 `hole()` 에서 계산해 `moveMade` 의 `marks` 에 넣는다.
    - ⑤ 아직 시작하지 않은 번호에 격자가 없어 막히면 그 번호까지 순서대로 만들고(C3) 한꺼번에 반영한다.

### P4. 04 창고 정리 (1차 — 기준은 A3·A3a)

(03 부품체크가 끝난 뒤.)

**번호마다 창고(slot) 정하기**
창고 0 = 메인, 1~5 = 따로 만드는 자리. 책을 번호 순서대로 보며 정한다. **1번은 창고 1에서 시작한다.**
1. 창고 정하는 세 가지(연달아 이어지는 번호 = 같은 창고, 새 세트 = 새 창고, "N + M" 합치기 = 앞 창고) → A3.

**스크립트에 적기**
- 번호마다 `kw["slot"] = 번호`. 앞 번호와 slot 이 바뀌면 `history` 글이 반드시 있어야 한다(`build.py` 검사). 창고·불러오기는 번호·설명 본문에 쓰지 않고 `history` 에만 쓴다. 예: "창고 1에서 불러와서 조립 → 그룹 1", "그룹 1 + 그룹 2 합침".
- 그룹 이름·`history` 에만 쓰는 것 → 규칙 A3.
- 다른 창고에서 작업하는 동안 안 보이게 둘 세트: 그 부품들에 `hideAt`(숨길 번호들), `store`({번호: "N번까지 만든 본체"}), `storeThumb`(사진). 사진은 사용자가 📷 썸네일 저장으로 만든다.
- "N~M번 2개 만들기"의 둘째 벌 복사(규칙 A3): M번 부품을 다 놓은 뒤 `s.copy_to_slot(Group("N~M번", [N~M번 부품 전부]), 창고번호, "보관 이름", until=꺼낼 번호)`. 부품마다 창고를 정하는 `slot` 은 화면(`design-assembly.js`)이 보관 카드와 창고 화면에 쓴다.
- 앞 번호에 사용자 ✓ 가 있을 때·`noGuide` → 규칙 A3.

**확인**
`python build.py <이름> --write` → 문제 0건, 그리고 `check_workspace(assemblyId)` (slot 빠짐, history 없음, store 없음).

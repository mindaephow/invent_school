# 규칙 정리 진행 (이어받는 Claude 는 이 파일과 `큐보/인수인계.md` 만 읽고 이어간다)

목표: 작업자가 이슈를 만나면 **상황 색인(증상 → 규칙 1~2개 → 도구 → 그래도 안 되면)** 으로 바로 찾아가 규칙대로만 하면 되게 한다. 규칙 파일은 줄이고, 본문은 색인이 가리킬 때만 연다.

## 사용자가 정한 것 (2026-11-15)
1. 색인은 표 한 장(증상 | 규칙 | 도구 | 그래도 안 되면), 규칙 파일 맨 위 0절에 두고 `number_start` 가 보여 준다.
2. 번호마다 읽는 것은 한화면 10줄 + 상황 색인. 규칙 파일 전체는 조립도를 시작할 때 한 번.
3. 지우는 것은 중복·날짜·사건 문구·빈 제목뿐이다. 지켜야 할 사실은 지우지 않는다.
4. `number_start` 는 이 번호의 상태·❌·다음 명령 + 한화면·색인만 낸다(규칙 설명 문장은 뺀다).
5. 번호 도중 도구 한계를 만나면 사유 주석이 붙은 손값(✋ 칩에 잡힘)으로 임시로 놓고 "도구 한계 ⚠"로 적은 뒤 다음 번호로 간다. 도구 수정은 모아서 따로 한다.
6. 번호 작업 세션은 조립 스크립트만 고친다. 공용 도구·규칙 문장은 고치지 않고 `규칙대기.md` 에 한 줄만 남긴다. 규칙 반영은 규칙 정리 세션이 한다.
7. 코드에만 있던 관례(연결점 기준점·T축 특례·`noMarkCheck`·좌표 변환)는 규칙 문장(K3·C6·G12)에 짧게 넣는다.
8. 책을 보는 과정과 3D 에 놓는 과정을 색인에서 잇는다(책 읽기 → 읽기 표 → 구멍·돌기 id → 6방향 대조 → 어긋나면 어느 쪽을 의심하는지).

## 건드리지 않는 것
- `kidknight.py`(조립도 작업 중), `asmlib.py` 의 `hostPose`(별도 작업).
- 푸시·커밋(사용자가 "업로드"라고 할 때만).
- 단계마다: 파일이 깨지지 않는 상태로 끝낸다 → `python handoff.py 규칙정리 --아이디 <계정> --어디까지 "…" --다음 "…"` → 아래 표 갱신.
- 수정 전 `python ladder.py "필요: …" "찾은 곳: …" "재사용: …"`(90분 유효).
- 시작 전 백업: `%TEMP%\invent_school_규칙백업_20261115\`(이 PC 에만 있다. 다른 PC 는 git 으로 되돌린다).

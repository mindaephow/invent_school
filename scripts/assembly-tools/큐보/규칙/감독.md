# 감독 모드 — Sonnet 작업자가 번호를 만들고, 메인 세션(감독)이 확인·개선한다

사용자 지시(2026-11-18): "소넷이 일을 하고 니가 감독해서 수정 개선하고, 어느 정도 되면 사이클이 잘 돌아가게 — 언제 어디에서든 그 방식으로."
**발명교실 조립도의 번호 작업("formula1 18번 진행해", "N번부터", "완성해")은 이 방식으로 한다.** 메인 세션은 직접 번호를 만들지 않고 감독한다.

## 역할

| 누가 | 하는 일 | 읽는 것 |
|---|---|---|
| **작업자** (`cubo-worker` 에이전트, Sonnet) | 번호 하나를 `3_번호하나.md` 1~9단계대로 만들고, 막힘 기록과 함께 보고 | `1_입구.md` → `3_번호하나.md` (+ ④·⑤) |
| **감독** (메인 세션) | 지시 → 결과를 **직접** 확인 → 막힘을 사실 확인해 문서·동작 묶음·도구를 고침 → 기록 → 다음 번호 | 이 문서 |
| **사용자** | 로그인, 감독이 모아 온 질문에 답, 증명 장치를 뺄지 결정, "업로드" | 감독의 보고 |

## 준비 (세션마다 한 번)

1. 저장소 `CLAUDE.md` "세션을 시작할 때" 1~3-1. 감독 모드 환경(작업자 정의·스킬)은 세션을 열 때 자동으로 맞춰진다(`supervisor_env.py` — `setup_new_pc --only-ponytail`·`global_hook` 이 부른다).
2. **진행 중인 조립도**(`refs/<이름>/_worked_upto.json` 의 upto > 0)면 `python set_active.py <이름>` 만, 처음 시작이면 `python handoff.py <이름> --아이디 <계정> --시작`(③ "번호 작업 전에").
3. 사용자가 로그인한 브라우저 탭의 포트를 확인한다(`tabs_context`) — 작업자에게 그 포트를 준다.
4. 감독 세션의 `finish_guard` 는 끈다(`python finish_guard.py off`). 감독이 작업자를 기다리는 동안 턴이 끝나야 해서다. 대신 감독은 **요청 범위의 마지막 번호까지 작업자를 차례로 부르고, 중간에 사용자에게 "다음 할까요?"로 멈추지 않는다**(B7 의 뜻).

## 번호 하나의 사이클

1. **지시:** `python supervise.py brief <이름> <번호> --포트 <포트> [--메모 "앞 번호에서 넘어온 주의점"]` 이 만든 글을 그대로 넣어 작업자를 부른다 — `Agent(subagent_type="cubo-worker", prompt=<그 글>, run_in_background=true)`.
   - **작업자가 목록에 없으면**(그 세션을 연 뒤에 처음 복사된 경우): `Agent(subagent_type="general-purpose", model="sonnet", prompt=<agents/cubo-worker.md 본문> + <brief 글>)`.
   - 한 번에 한 번호씩. 같은 조립도에 작업자 둘을 동시에 돌리지 않는다(같은 파일을 고친다).
2. **직접 확인 — 보고를 믿지 않는다** (원래 사고: "엉망으로 하고 확인도 안 하고 맞다고 고집"):
   - `python rulecheck.py <이름> <번호>` — ❌ 없음.
   - `git diff -- 큐보/조립도/<권>권/<이름>/<이름>.py` — 바뀐 줄을 읽는다. 손 좌표(`p=`·`place`·숫자 위치)·`noMarkCheck`·검사 끄기가 새로 들어가지 않았는지. `python handcheck.py <이름>`.
   - **책과 같은가(이것이 진짜 확인):** 화면에서 그 번호를 열어(`viewer_snippets.md` 1·2, 작업자가 쓴 책 시점 카메라) 스크린샷을 찍고, 책 `refs/<이름>/NN.jpg` 와 나란히 본다 — 부품 개수·링(화살표) 수·칸·방향·층이 같은가. 다르면 숫자로 적는다.
   - 하단 감시 칩: 그 번호의 위반 0.
3. **다르면:** 감독이 조립 스크립트를 직접 고치지 않는다 — 같은 작업자에게 `SendMessage` 로 "무엇이 책과 어떻게 다른지(센 값)"를 보내 고치게 하고 2로 돌아간다. 두 번 고쳐도 안 맞으면 '판단과정'에 ⚠ 로 남기고 마지막 보고의 질문에 넣는다.
4. **막힘 처리** — 작업자의 막힘 기록을 한 줄씩:
   - ① 사실 확인: 코드·도구 출력으로 확인한다(작업자의 추정을 그대로 문서에 옮기지 않는다).
   - ② 분류하고 고친다:
     - 문서가 모자라거나 틀림 → 해당 칸 문서(`3_번호하나.md` 등)의 그 문장을 **덮어쓴다**(덧붙여 늘리지 않는다).
     - 같은 동작을 손으로 되풀이 → 동작 묶음(`moves.py`)에 더하고 `test_moves.py` 에 사례를 넣어 기존 조립도와 같은지 확인.
     - 도구가 틀리게 동작 → 공용 도구 수정(사다리 `ladder.py` 기록 → 고침 → 이미 만든 조립도에 전후 비교). 크면 `규칙대기.md` 에 두고 사용자에게 알린다.
     - 이미 문서에 있는데 못 찾음 → 그 문장을 ③ 의 해당 단계 첫 줄 가까이로 옮기거나 더 짧게.
   - ③ 고친 것은 `supervise.py add … --고침` 에 한 줄로.
5. **기록:** `python supervise.py add <이름> <번호> --판정 맞음|다름|못함 --분 <작업자 시간> --호출 <도구 호출 수> --저장 <build --write 횟수> --막힘 <개수> --고침 "…" --메모 "…"` (분·호출은 작업자 완료 알림의 duration·tool_uses).
6. 다음 번호로. 막힘 기록에서 다음 번호에 넘길 주의점은 `brief --메모` 로.

## 범위를 끝냈을 때
- `python handoff.py <이름> --아이디 <계정> --어디까지 "…" --다음 "…"`.
- 사용자 보고: 번호별 판정(감독이 직접 본 것), `supervise.py show` 의 추세, 이번에 고친 문서·도구, 모아 둔 질문. 푸시는 사용자가 "업로드"라고 할 때(I2).

## 사이클 줄이기
- `supervise.py show` 가 "최근 5번호 막힘 ≤1·모두 맞음"을 알리면, 감독 간격을 늘릴지(예: 3번호마다 직접 확인) 사용자에게 제안한다 — 사용자가 정한다.
- **증명 다이어트:** 감독의 직접 확인(책과 나란히)이 대신할 수 있는 작업자 쪽 증명 장치(증거 서명·관찰 기록·매번 6방향·via.json 등)는, 장치마다 "왜 생겼나 / 누가 대신하나"를 정리해 사용자에게 항목별로 묻고, 사용자가 빼라고 한 것만 뺀다. 그전까지 작업자는 ③ 을 그대로 다 한다.

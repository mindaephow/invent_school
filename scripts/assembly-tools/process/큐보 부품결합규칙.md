# 큐보 부품 결합규칙 (사용자 확정 규칙의 원본)

**큐보 부품에만 적용한다.** 에이스랩·로보타미주니어·프로보는 부품 규격과 결합 방식이 달라 따로 정리한다(아직 안 함).
점검 도구: `python cubo_joint_check.py <이름|all> [번호]` — 규칙 2·5~10·13~15를 잰다. 규칙 1·3·4·12와 [미정] 항목은 아직 점검이 없다.
규칙 문장은 이 파일이 원본이다. 규칙을 바꾸면 이 파일만 덮어쓰고(옛 문장은 지운다), 도구에 올릴 수 있는 것은 `cubo_joint_check.py` 로 올린다. `[확정]` 은 사용자가 직접 말한 것, `[집계]` 는 조립도 20개에서 센 값(확인 전), `[가정]` 은 내 추정이다.

## 사용자가 정한 결합 규칙

# 사용자가 정해 준 바른 결합 규칙 (이것이 기준 — 집계값과 다르면 이쪽이 우선)

1. 프레임과 프레임을 연결하는 방법은 리벳, 블록.
2. 프레임을 리벳으로 결합했을 경우 프레임 사이에 벌어짐은 없다(틈 0).
3. 프레임과 프레임은 물리적으로 겹칠 수 없다.
4. 블록의 돌기는 프레임과 결합할 때 프레임의 면을 벗어나지 않는다.
5. 블록의 돌기는 프레임 두 개를 결합할 수 없다.
6. 프레임에 결합하는 서보모터·DC모터의 돌기는 블록 돌기와 길이가 비슷하므로 블록 돌기와 같은 규칙을 따른다(프레임 면을 벗어나지 않음, 프레임 두 개를 결합할 수 없음).
7. 큐보 돌기(리벳·블록·서보·DC모터 모두)는 길이가 판 두께(5mm)쯤이라 프레임 두 장을 통과할 수 없다 — 돌기 하나는 프레임 한 장의 구멍에만 들어간다. 리벳은 양 끝 돌기가 각각 한 장씩 맡아 두 장을 묶는다.
8. 리벳으로 결합한 모든 부품 사이에는 틈이 없다 — 프레임↔프레임뿐 아니라 블록↔프레임, 15프레임↔135도 프레임 등 리벳이 잇는 모든 쌍(규칙 2를 넓힘). 예: 드롭체커 8번 15프레임↔135도 프레임이 벌어져 있음(틀림).
9. 나사(볼트)로 결합하면 부품 사이에 틈이 없고, 나사 머리·끝이 프레임 면 위로 튀어나오지 않는다(드롭체커 8번 지적).
(가정 — 사용자 확인 전) 메인보드 돌기도 규칙 6과 같다고 보고 점검기에 넣어 둠. 집계에서 블록·모터와 같은 모양(깊이 0.0 89%)이라서.
10. 방향 있는 부품(메인보드 등)은 책 그림에 보이는 부품 모양·특징(버튼 줄·단자·케이블)과 같은 방향으로 둔다. 돌기만 맞추면 안 된다. 방향의 기준은 월드 X·Y·Z 가 아니라 같은 로봇 안의 다른 부품과의 상대 관계(예: 메인보드 버튼 쪽은 뒷판 반대쪽)다 — 완성품 놓는 방향이 조립도마다 달라서. 점검: cubo_joint_check.py 규칙10 + <조립도>_orient.json.
11. 메인보드의 방향은 무조건 로봇의 앞·뒤 또는 위·아래를 기준으로 정한다(버튼 줄이 로봇 앞쪽·뒤쪽인지, 윗면이 로봇 위·아래인지 책에서 읽어 <조립도>_orient.json 에 face 로 적는다).
12. 메인보드는 검은색이고 윗면의 노란 버튼 4개가 무조건 L 자 또는 ㄴ 자 모양으로 놓인다(큰 버튼 하나도 노란 버튼이다 — 검은 받침은 보드 몸체 색일 뿐, 별도의 검정 버튼이 아님. 책 롤링봇 12번·24번 확대로 확인: 작은 것·큰 것·작은 것·작은 것 순서). 이 모양이 곧 방향을 정한다(11번 앞·뒤 또는 위·아래와 같은 규칙, 점검기 규칙10에 반영됨).
13. 프레임과 블록을 돌기로 바로 결합할 때도 틈이 없다(리벳으로 결합할 때와 같다, 규칙 8). 모터·메인보드·센서의 돌기 결합도 같게 본다. 점검: cubo_joint_check.py 규칙13.
14. 8볼트와 너트로 프레임 2개를 결합할 때도 틈이 없다(프레임 2장이 딱 붙고 볼트가 그 두 장을 지나 너트로 조인다, 판 두께 합 10mm).
15. 12볼트와 너트로 프레임 3개를 결합할 때도 틈이 없다(프레임 3장이 딱 붙고 볼트가 세 장을 지나 너트로 조인다, 판 두께 합 15mm).
16. [확정, 사용자 2026-11-03] 프레임과 프레임이 옆에 이어질 때는 어떤 방향으로 놓아도 맞닿은 구멍 사이 피치가 항상 같다(10mm). 구멍 격자가 판을 건너 그대로 이어진다. 점검: cubo_joint_check.py 규칙16.
17. [확정, 사용자 2026-11-03] 프레임은 물리적으로 겹칠 수 없다(가장 기본 규칙). 점검: cubo_joint_check.py 규칙3.
18. [확정, 사용자 2026-11-03] 볼트 머리는 맨 위 프레임의 홀 테두리 안에 들어가고, 너트 아래 턱은 맨 아래 프레임의 홀 테두리에 들어간다(각 약 1mm). 그래서 12볼트(몸통 11.6+머리 1)가 프레임 3장(15mm)을 지난다. 머리·너트가 판에서 -1.0mm 들어가는 것은 정상이고, 판 밖으로 튀어나오거나 떠 있거나 더 깊이 파묻히면 위반. 점검: cubo_joint_check.py 규칙9.

19. [확정, 사용자 2026-11-04] **볼트·너트·축을 뺀 돌기(블록·눈블록·DC모터·서보모터·메인보드·센서 등)는 크기가 모두 같아야 한다**(지름 6.8, 길이 5 — 위 "부품별 확정 수치"의 블록 돌기). 돌기와 결합하는 프레임·블록의 구멍도 같다(지름 7). **리벳은 스냅핏 방식으로 들어가므로 조금 달라도 된다.** 볼트·너트·축은 용도가 달라 이 규칙의 대상이 아니다.
   [반영함, 2026-11-04] DB 연결점의 서보모터 뒷면 p2~p4(원래 지름 5, 길이 4·2·2)와 IR센서·LED센서·터치센서 돌기(원래 지름 5, 길이 5.83)를 지름 6.8·길이 5 로 맞췄다(원래 값은 백업). **3D 모델(STL)의 돌기도 같은 규격 돌기로 바꿨다**(`cubo-block-mesh.js` 의 `addPeg` — 밑동 1mm 반지름 3.4·몸통 2.9·끝 2.4·십자 홈 1.2, 돌기 하나 삼각형 246개). 옛 서보모터 돌기는 지름 5(p2 길이 4·p3/p4 길이 2)였고 옛 센서 돌기는 속이 빈 관이었다. 길이 5 는 몸통 면(밑동 1mm 포함)에서 잰다. 서보모터 p2~p4 중심은 y=-21.75, 센서는 돌기가 0.833 짧아져 모델 가운데가 움직인 만큼 연결점 y 를 0.4165 낮췄다. 원본 모델·연결점은 GitHub `scripts/assembly-tools/부품원본_백업_2026-11-04/` 에 있다. 출력용(인쇄용) 데이터는 건드리지 않았다. 서보모터 출력축 p1 은 서보혼용 축이라 이 규칙 대상이 아니다. 조립 프로그램 사본 `conn.json` 은 아직 옛 값이다. 부품 3D 썸네일은 다시 만들지 않았다.

## 물리적으로 안 되는 것 (결합 원리)

- [확정, 사용자 2026-11-04] **결합은 물리적으로 지나갈 수 없는 것과 겹칠 수 없는 것을 따른다.** 조립도·3D 부품·결합원리 화면 모두 이 원리로 판단한다.
- **부품끼리는 겹칠 수 없다.** 프레임끼리도 겹칠 수 없다(위 규칙 3·17).
- **구멍보다 큰 것은 지나갈 수 없다.** 대가리(볼트·너트·T축·서보고정볼트의 머리)는 프레임 홀(홀 테두리)에 맞춰서 끼워지고 통과할 수 없다 — 구멍의 좁은 곳(반지름 2.75)보다 커서 지나가지 못하고 멈춘다(사용자 2026-11-04). 프레임에서는 머리가 홀 테두리(안쪽 반지름 3.5)에 맞춰 쏙 들어가 프레임 면과 같아진다. 홀 테두리가 없는 작은기어에서는 T축 머리가 기어 구멍을 지나가지 못하고 기어 윗면에 닿아 멈추며 머리가 밖으로 남는다(옛 "머리 2mm"는 예시 숫자).
- **돌기 하나는 프레임 한 장의 구멍에만 들어간다.** 돌기 길이가 판 두께(5mm)쯤이라 프레임 두 장을 통과할 수 없다(위 규칙 5·7). 리벳은 양 끝 돌기가 각각 한 장씩 맡아 두 장을 묶는다.
- 새 결합을 만들 때는 먼저 "어디에서 물리적으로 멈추는가, 무엇과 겹치는가"를 따져 보고, 모델이 이 원리와 어긋나면 부품 모델을 고친다(예: 8볼트·12볼트 머리가 홀 테두리에 안 들어가는 크기였다).

## 부품별 어떻게 결합하나

# 부품별 "어떻게 결합하나" 정리. [확정] = 사용자가 정해 준 것, [집계] = 조립도 20개에서 센 것(사용자 확인 전, 틀릴 수 있음)

■ 리벳
 [확정] 양 끝 돌기(p1·p2)가 각각 구멍 한 장에만 들어간다 → 두 부품을 한 장씩 맡아 묶는다. 돌기 하나가 판 두 장을 못 뚫는다(돌기 길이 ≈ 판 두께 5mm).
 [확정] 리벳으로 묶은 두 부품 사이엔 틈이 없다(프레임↔프레임, 블록↔프레임, 15프레임↔135도 프레임 등 전부).
 [집계] 꽂히는 곳: 프레임(1498건), 3단블록(158), 2단블록(79), 2열브라켓(76), 큰기어(34), 1열브라켓(20).
 [집계] 구멍 한가운데에서 0.5mm(프레임·브라켓), 2.0mm(3단블록), 1.5mm(2단블록·큰기어) 지점에 앉는다.
■ 블록(2단·3단·눈블록)
 [확정] 블록 돌기는 프레임 한 장의 구멍에만 들어가고, 프레임 면 밖으로 나오지 않는다. 프레임 두 장을 한 돌기로 못 묶는다.

 [집계] DC모터 → 프레임 170건, 깊이 0.0 85~100%.

IR·LED센서는 [미정].

## 부품 연결점(돌기·구멍) — 어디에 있고 어떻게 확인하나

**원본은 DB** 다 — `ivs_part_catalog` 의 `data.connectors`(부품마다 `pegs` 돌기·`holes` 구멍: `id`·`pos`·`dir`·`r` 반지름·`len`·`through`, 부품 `size`, `confidence`). 안내점(`marks`·`dir`)은 이 연결점에서 `asmlib.py` 가 계산한다(조립도에 따로 적지 않는다). 연결점이 어긋나면 안내점도 어긋난다.

| 무엇 | 어디 |
|---|---|
| 원본(읽기·고치기) | MCP `get_part_connectors` · `set_part_connectors`, 화면: 설계 화면 0차시 "큐보 부품 전체 리스트" → 부품마다 🟢 연결점 버튼 |
| **부품 상세 내역(매번 다시 확인하지 않게)** | DB 부품 행의 `data.detail`(2026-11-04 큐보 51종에 채움): 크기, 돌기·구멍 개수와 번호·위치·방향·지름·길이·관통, 규칙 수치, 대가리·몸통 방향, 등록값이 규칙과 다른 점, 알아 둘 것(사용자 확정·STL 실측 포함). `run_sql` 로 `data->'detail'` 을 읽는다. 연결점·규칙을 고치면 이 항목도 같이 고친다(자동 갱신 아님). 크기·구멍 번호는 연결점 좌표(y 가 위)와 같은 기준이다 |

**확인하는 순서**
1. `check_chapter_parts(권, 차시)` — 부품마다 연결점의 `confidence`(`checked` 확인함 / `auto` 자동탐지·확인 필요 / 없음)와 면 이름 확정 여부를 본다. `auto`·없음은 번호 조립 전에 확인한다(`03_부품체크.md` A).
2. `get_part_connectors(부품)` — DB 에 등록된 현재 값. `conn.json` 사본과 **구멍·돌기 번호(id)까지** 같은지 본다(번호가 바뀌어 있으면 스크립트가 다른 구멍을 가리킨다 — 2026-11-04 2열브라켓 h2·h3 가 DB 와 conn.json 에서 서로 바뀌어 있었다).
3. `measure_part(부품)` — 3D 모델(STL)을 재서 등록값과 ✓ 일치 / △ 차이 / ✗ 못 찾음 / ➕ 등록 안 됨으로 대조한다. **한계: 둥근 벽만 찾는다.** 십자·소켓·네모 구멍과 블록 돌기·리벳·T축·기어처럼 둥글지 않거나 홈이 있는 모양은 "못 찾음"이 나오는데, 이것은 틀렸다는 뜻이 아니다. 도형으로 만든 프레임(N프레임)은 대상이 아니다. 구멍은 홀 테두리(지름 8, 깊이 1)와 안쪽 관통 구멍이 따로 잡혀 등록값(관통 한 개)과 숫자가 달라 보일 수 있다.
4. 3D 뷰어 🟢 연결점 버튼 — 돌기·구멍 개수와 위치를 눈으로 세어 본다(자동탐지 부품은 반드시).
5. 숫자 기준은 아래 "부품별 확정 수치" 와 위 규칙 1~18 이다(예: 프레임 구멍 지름 7(r 3.5)·관통·두께 5·간격 10, 블록 돌기 지름 6.8·길이 5, 블록 구멍 지름 7·길이 10·관통, 리벳 지름 6.2). 이 수치와 다른 등록값은 부품마다 따로 보정하지 않고 한꺼번에 맞춘다.

**고칠 때 순서**: DB(`set_part_connectors`) → `partlib.py` `OTHER` → `python partlib.py`(conn.json·dims.json 다시 만듦) → 그 부품이 쓰인 조립도를 다시 만들어(`python <이름>.py`) `python cubo_joint_check.py <이름>` 이 0건인지 본다. 연결점을 바꾸면 그 부품을 쓰는 모든 조립도의 결합 점검이 달라질 수 있어 범위를 먼저 센다.

## 양쪽 면이 다른 부품 — A면·B면으로 따로 표시

양쪽 면의 모양이 다른 부품은 면을 구분해서 적는다. 지금은 면 이름이 모델 축(홀면 +y / −y)뿐이라 양쪽이 같은 구멍·같은 번호로 보여 어느 쪽인지 알 수 없다(부시 `h1` 이 두 면에서 같음).

- [확정, 사용자 2026-11-04] **부시·너트·T축·볼트·스프라켓은 대가리가 있는 부품으로 다룬다.** 면은 대가리 쪽과 몸통 쪽으로 나뉜다.
- [확정, 사용자 2026-11-04] **스프라켓은 넓은 톱니 부분이 대가리다.**
- [확정, 사용자 2026-11-04] **부시와 너트도 넓은 지름 부분을 대가리라고 부른다**(볼트·T축의 머리와 같은 말).
- [확정, 사용자 2026-11-04] **부시와 너트는 대가리 부분이 바깥쪽이다.**
- **대가리가 모델 어느 쪽인가**(부품 모델 축은 부품마다 다르다 — 쓸 때는 이 표로 대가리 쪽을 찾는다):

| 부품 | 대가리 | 몸통 | 근거 |
|---|---|---|---|
| 부시 | −y (넓은 지름 쪽, 바깥) | +y (좁은 지름 쪽, 판 쪽) | `00_규칙.md` G5 |
| 너트 | −y (넓은 지름 쪽, 머리·턱) | +y (좁은 지름 쪽, 몸통 돌기) | G3, 연결점 `p1` 방향 +y |
| T축 | −y (둥근 접시) | +y (십자 끝, 꽂는 쪽) | 안내서 4-1, 연결점 `p1` 방향 +y |
| 8볼트·12볼트·서보고정볼트 | +y (머리) | −y (나사 돌기) | 연결점 `p1` 방향 −y(등록값, 눈으로 확인 전) |
| 스프라켓 | −y (넓은 톱니 부분) | +y (허브 관) | `00_규칙.md` G6 "돌기(+y 허브 관)"(등록값 `h1` 방향 −y, 눈으로 확인 전) |

- [가정 — 사용자 확인 전] 이름: **A면 = 몸통 쪽(판 구멍에 먼저 들어가는 면) / B면 = 대가리 쪽(바깥에 보이는 면).** 모델 축 부호는 위 표대로 부품마다 반대일 수 있다(볼트는 대가리가 +y). 연결점 구멍 번호에 A·B 를 붙이는 일은 아직 안 했다.
- [확정, 사용자 2026-11-04] **눈블록과 바퀴(작은바퀴·데코바퀴·중간바퀴)는 돌기가 분명해서 방향이 돌기로 정해진다 — 대가리 구분(A면·B면)을 따로 하지 않는다.**
- 이 밖에 양쪽이 다른 부품(서보혼 등)은 사용자가 정하면 여기에 추가한다 — 아직 정하지 않았다.

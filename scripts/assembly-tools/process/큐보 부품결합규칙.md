# 큐보 부품 결합규칙 (사용자 확정 규칙의 원본)

**큐보 부품에만 적용한다.** 에이스랩·로보타미주니어·프로보는 부품 규격과 결합 방식이 달라 따로 정리한다(아직 안 함).
점검 도구: `python cubo_joint_check.py <이름|all> [번호]` — 규칙 2·5~10·13~15를 잰다. 규칙 1·3·4·12와 [미정] 항목은 아직 점검이 없다.
**부품 자체의 크기·돌기·구멍 숫자는 이 파일에 따로 두지 않고 부품 DB 의 상세내역(`ivs_part_catalog` 의 `data.detail`)을 기준으로 한다**(사용자 지시 2026-11-04). 부품 숫자는 상세내역에만 있고 다른 곳(이 파일·조립 스크립트·문서)에는 적지 않는다. 이 파일은 결합 규칙(틈·겹침·돌기·방향)만 정한다.
규칙 문장은 이 파일이 원본이다. 규칙을 바꾸면 이 파일만 덮어쓰고(옛 문장은 지운다), 도구에 올릴 수 있는 것은 `cubo_joint_check.py` 로 올린다. `[확정]` 은 사용자가 직접 말한 것, `[집계]` 는 조립도 20개에서 센 값(확인 전), `[가정]` 은 내 추정이다.

## 0. 물리법칙이 가장 우선이다 (결합 규칙 전체의 바탕)

- [확정, 사용자 2026-11-05] **모든 결합의 가장 큰 우선순위는 물리법칙이다 — 숨쉬듯이 바탕에 깔려 있는 규칙이다.** 조립도·3D 부품·결합원리 화면 모두 이 원리로 판단하고, 아래 모든 규칙은 이 위에서 읽는다. 위치를 정한 뒤에는 반드시 "어디에서 물리적으로 멈추는가, 무엇과 겹치는가"를 따져 보고, 모델이 이 원리와 어긋나면 번호가 아니라 도구·부품 모델을 고친다(예: 8볼트·12볼트 머리가 홀 테두리에 안 들어가는 크기였다).
- [확정, 사용자 2026-11-05] **면과 면은 자석처럼 붙는다 — 물리법칙을 무시하고 겹치거나 침범하면 안 된다(틈도 없다).** 홀처럼 뚫린 곳을 통과하거나 돌기가 구멍에 들어가는 것은 겹침이 아니다(T축이 기어·프레임 구멍을 지나는 것 등) — 이 규칙은 구멍이 아닌 몸통·면끼리의 겹침이다. 도구: `asmlib.py place_rest`(몸통 크기 기준으로 끝면에 닿게 놓음), `attach`/`recv`(돌기 끝이 구멍 면에 닿게 놓음).
- **부품끼리는 겹칠 수 없다.** 프레임끼리도 겹칠 수 없다(규칙 3·17). 겹침은 구멍 길이가 아니라 **실제 모양**으로 판단한다 — 부품 몸통 크기(`dims.json`·STL)와 홀 테두리(판 면 위로 솟은 고리)까지 포함한다(2026-11-05: 구멍 길이로 기어를 놓아 몸통이 홀 테두리를 파고듦).
- **구멍보다 큰 것은 지나갈 수 없다.** 대가리(볼트·너트·T축·서보고정볼트의 머리)는 프레임 홀(홀 테두리)에 맞춰서 끼워지고 통과할 수 없다 — 구멍의 좁은 곳보다 커서 지나가지 못하고 멈춘다(사용자 2026-11-04). 프레임에서는 머리가 홀 테두리에 맞춰 쏙 들어가 프레임 면과 같아진다.
- **T축은 끝까지 끼운다.** 홀 테두리가 없는 작은기어에서는 T축 머리가 기어 구멍을 지나가지 못하고 기어 윗면에 닿아 멈추며 머리가 기어 밖으로 남는다 — 남는 두께는 머리 두께(둥근 접시, 두께는 T축 STL 실측값 — 부품 상세내역에 아직 없음)이고 "2mm" 는 옛 예시였다(사용자 2026-11-04 정정). 세로·가로 모두, 띄운 모습은 그대로 두고 제자리만. 도구: `asmlib.py attach` 가 기어에 끼우는 T축을 머리 두께(`T_HEAD_OUT`)만큼 올려 놓는다. 프레임에 끼우는 T축은 도구가 아직 검증하지 못한다(눈으로 확인).
- **[확정, 사용자 2026-11-04] 축(T축)의 끝이 구멍 안에 그냥 들어가 있는 것은 결합이 아니다.** 돌기가 구멍에 들어가 있어도 꽂아 고정하는 결합(안내 화살표·안내점이 필요한 결합)은 책이 초록 링과 화살표로 보여 주는 것만이다. 길이가 긴 T축이 프레임·부시를 지나 끝이 아래 프레임 구멍에 들어가 있는 정도는 결합으로 세지 않고, 합치는 번호에서도 T축에는 합치기 안내점을 요구하지 않는다(안내는 구멍을 받는 부품이 맡는다). 도구: `check_local.js` 의 settle 검사가 T축을 건너뛴다.
- **돌기 하나는 프레임 한 장의 구멍에만 들어간다.** 돌기 길이가 판 한 장 두께쯤이라 프레임 두 장을 통과할 수 없다(규칙 5·7). 리벳은 양 끝 돌기가 각각 한 장씩 맡아 두 장을 묶는다.

## 사용자가 정한 결합 규칙

# 사용자가 정해 준 바른 결합 규칙 (이것이 기준 — 집계값과 다르면 이쪽이 우선)

1. 프레임과 프레임을 연결하는 방법은 리벳, 블록.
2. 프레임을 리벳으로 결합했을 경우 프레임 사이에 벌어짐은 없다(틈 0).
3. 프레임과 프레임은 물리적으로 겹칠 수 없다.
4. 블록의 돌기는 프레임과 결합할 때 프레임의 면을 벗어나지 않는다.
5. 블록의 돌기는 프레임 두 개를 결합할 수 없다.
6. 프레임에 결합하는 서보모터·DC모터의 돌기는 블록 돌기와 길이가 비슷하므로 블록 돌기와 같은 규칙을 따른다(프레임 면을 벗어나지 않음, 프레임 두 개를 결합할 수 없음).
7. 큐보 돌기(리벳·블록·서보·DC모터 모두)는 길이가 판 한 장 두께쯤이라 프레임 두 장을 통과할 수 없다 — 돌기 하나는 프레임 한 장의 구멍에만 들어간다. 리벳은 양 끝 돌기가 각각 한 장씩 맡아 두 장을 묶는다.
   [도구] `asmlib.py` recv 가 이 규칙을 자동 적용한다 — 이미 다른 프레임 구멍에 든 돌기(리벳·블록 등, 축·볼트·너트 제외)는 결합·안내점에서 빼고 '[규칙 자동]' 으로 알린다(손으로 번호마다 빼지 않는다, 2026-11-04).
8. 리벳으로 결합한 모든 부품 사이에는 틈이 없다 — 프레임↔프레임뿐 아니라 블록↔프레임, 15프레임↔135도 프레임 등 리벳이 잇는 모든 쌍(규칙 2를 넓힘). 예: 드롭체커 8번 15프레임↔135도 프레임이 벌어져 있음(틀림).
9. 나사(볼트)로 결합하면 부품 사이에 틈이 없고, 나사 머리·끝이 프레임 면 위로 튀어나오지 않는다(드롭체커 8번 지적).
(가정 — 사용자 확인 전) 메인보드 돌기도 규칙 6과 같다고 보고 점검기에 넣어 둠. 집계에서 블록·모터와 같은 모양(깊이 0.0 89%)이라서.
10. 방향 있는 부품(메인보드 등)은 책 그림에 보이는 부품 모양·특징(버튼 줄·단자·케이블)과 같은 방향으로 둔다. 돌기만 맞추면 안 된다. 방향의 기준은 월드 X·Y·Z 가 아니라 같은 로봇 안의 다른 부품과의 상대 관계(예: 메인보드 버튼 쪽은 뒷판 반대쪽)다 — 완성품 놓는 방향이 조립도마다 달라서. 점검: cubo_joint_check.py 규칙10 + <조립도>_orient.json.
11. 메인보드의 방향은 무조건 로봇의 앞·뒤 또는 위·아래를 기준으로 정한다(버튼 줄이 로봇 앞쪽·뒤쪽인지, 윗면이 로봇 위·아래인지 책에서 읽어 <조립도>_orient.json 에 face 로 적는다).
12. 메인보드는 검은색이고 윗면의 노란 버튼 4개가 무조건 L 자 또는 ㄴ 자 모양으로 놓인다(큰 버튼 하나도 노란 버튼이다 — 검은 받침은 보드 몸체 색일 뿐, 별도의 검정 버튼이 아님. 책 롤링봇 12번·24번 확대로 확인: 작은 것·큰 것·작은 것·작은 것 순서). 이 모양이 곧 방향을 정한다(11번 앞·뒤 또는 위·아래와 같은 규칙, 점검기 규칙10에 반영됨).
13. 프레임과 블록을 돌기로 바로 결합할 때도 틈이 없다(리벳으로 결합할 때와 같다, 규칙 8). 모터·메인보드·센서의 돌기 결합도 같게 본다. 점검: cubo_joint_check.py 규칙13.
14. 8볼트와 너트로 프레임 2개를 결합할 때도 틈이 없다(프레임 2장이 딱 붙고 볼트가 그 두 장을 지나 너트로 조인다).
15. 12볼트와 너트로 프레임 3개를 결합할 때도 틈이 없다(프레임 3장이 딱 붙고 볼트가 세 장을 지나 너트로 조인다).
16. [확정, 사용자 2026-11-03] 프레임과 프레임이 옆에 이어질 때는 어떤 방향으로 놓아도 맞닿은 구멍 사이 피치가 항상 같다. 구멍 격자가 판을 건너 그대로 이어진다. 점검: cubo_joint_check.py 규칙16.
17. [확정, 사용자 2026-11-03] 프레임은 물리적으로 겹칠 수 없다(가장 기본 규칙). 점검: cubo_joint_check.py 규칙3.
18. [확정, 사용자 2026-11-03] 볼트 머리는 맨 위 프레임의 홀 테두리 안에 들어가고, 너트 아래 턱은 맨 아래 프레임의 홀 테두리에 들어간다. 머리·너트가 판 면에서 홀 테두리 깊이만큼 들어가는 것은 정상이고, 판 밖으로 튀어나오거나 떠 있거나 더 깊이 파묻히면 위반. 점검: cubo_joint_check.py 규칙9.

19. [확정, 사용자 2026-11-04] **볼트·너트·축을 뺀 돌기(블록·눈블록·DC모터·서보모터·메인보드·센서 등)는 크기가 모두 같아야 한다**(크기는 부품 상세내역). 돌기와 결합하는 프레임·블록의 구멍도 같다. **리벳은 스냅핏 방식으로 들어가므로 조금 달라도 된다.** 볼트·너트·축은 용도가 달라 이 규칙의 대상이 아니다. 서보모터 출력축 p1 은 서보혼용 축이라 이 규칙 대상이 아니다.

## 부품 연결점(돌기·구멍) — 어디에 있고 어떻게 확인하나

**원본은 DB 의 부품 상세내역(`data.detail`)이다** — 크기·돌기·구멍 번호·위치·방향·지름·길이·관통이 있고, 이것이 기준이다. 같은 내용의 연결점 `data.connectors`(부품마다 `pegs` 돌기·`holes` 구멍: `id`·`pos`·`dir`·`r` 반지름·`len`·`through`, 부품 `size`, `confidence`). 안내점(`marks`·`dir`)은 이 연결점에서 `asmlib.py` 가 계산한다(조립도에 따로 적지 않는다). 연결점이 어긋나면 안내점도 어긋난다.

| 무엇 | 어디 |
|---|---|
| 원본(읽기·고치기) | MCP `get_part_connectors` · `set_part_connectors`, 화면: 설계 화면 0차시 "큐보 부품 전체 리스트" → 부품마다 🟢 연결점 버튼 |
| **부품 상세 내역(매번 다시 확인하지 않게)** | DB 부품 행의 `data.detail`(2026-11-04 큐보 51종에 채움): 크기, 돌기·구멍 개수와 번호·위치·방향·지름·길이·관통, 규칙 수치, 대가리·몸통 방향, 등록값이 규칙과 다른 점, 알아 둘 것(사용자 확정·STL 실측 포함). `run_sql` 로 `data->'detail'` 을 읽는다. 연결점·규칙을 고치면 이 항목도 같이 고친다(자동 갱신 아님). 크기·구멍 번호는 연결점 좌표(y 가 위)와 같은 기준이다 |
| 조립 프로그램용 사본 | `scripts/assembly-tools/conn.json`(+`dims.json`) — `partlib.py` 가 만든다. **사본이라 DB 와 어긋날 수 있다(2026-11-04: 블록·리벳 수치와 2열브라켓 번호가 DB 와 달랐다 — 숫자는 DB 가 기준).** N프레임은 규칙(구멍 10mm 격자, 두께 5)으로 계산하고, 나머지는 DB 값을 `partlib.py` 의 `OTHER` 에 옮겨 적은 것 |
| 부품 크기 | 부품 상세내역 `data.detail` 의 `크기_mm` — 별도 크기 표는 없다 |

**확인하는 순서**
1. `check_chapter_parts(권, 차시)` — 부품마다 연결점의 `confidence`(`checked` 확인함 / `auto` 자동탐지·확인 필요 / 없음)와 면 이름 확정 여부를 본다. `auto`·없음은 번호 조립 전에 확인한다(`03_부품체크.md` A).
2. `get_part_connectors(부품)` — DB 에 등록된 현재 값. `conn.json` 사본과 **구멍·돌기 번호(id)까지** 같은지 본다(번호가 바뀌어 있으면 스크립트가 다른 구멍을 가리킨다 — 2026-11-04 2열브라켓 h2·h3 가 DB 와 conn.json 에서 서로 바뀌어 있었다).
3. `measure_part(부품)` — 3D 모델(STL)을 재서 등록값과 ✓ 일치 / △ 차이 / ✗ 못 찾음 / ➕ 등록 안 됨으로 대조한다. **한계: 둥근 벽만 찾는다.** 십자·소켓·네모 구멍과 블록 돌기·리벳·T축·기어처럼 둥글지 않거나 홈이 있는 모양은 "못 찾음"이 나오는데, 이것은 틀렸다는 뜻이 아니다. 도형으로 만든 프레임(N프레임)은 대상이 아니다. 구멍은 홀 테두리와 안쪽 관통 구멍이 따로 잡혀 등록값(관통 한 개)과 숫자가 달라 보일 수 있다.
4. 3D 뷰어 🟢 연결점 버튼 — 돌기·구멍 개수와 위치를 눈으로 세어 본다(자동탐지 부품은 반드시).
5. 숫자 기준은 부품 상세내역(`data.detail`)이다 — 크기·구멍 지름·돌기 지름·길이는 상세내역을 읽는다. 상세내역과 다른 등록값은 부품마다 따로 보정하지 않고 한꺼번에 맞춘다.

**고칠 때 순서**: DB(`set_part_connectors`) → `partlib.py` `OTHER` → `python partlib.py`(conn.json·dims.json 다시 만듦) → 그 부품이 쓰인 조립도를 다시 만들어(`python <이름>.py`) `python cubo_joint_check.py <이름>` 이 0건인지 본다. 연결점을 바꾸면 그 부품을 쓰는 모든 조립도의 결합 점검이 달라질 수 있어 범위를 먼저 센다.

## 양쪽 면이 다른 부품 — A면·B면으로 따로 표시

양쪽 면의 모양이 다른 부품은 면을 구분해서 적는다. 지금은 면 이름이 모델 축(홀면 +y / −y)뿐이라 양쪽이 같은 구멍·같은 번호로 보여 어느 쪽인지 알 수 없다(부시 `h1` 이 두 면에서 같음).

- [확정, 사용자 2026-11-04] **부시·너트·T축·볼트·스프라켓은 대가리가 있는 부품으로 다룬다.** 면은 대가리 쪽과 몸통 쪽으로 나뉜다.
- [확정, 사용자 2026-11-04] **스프라켓은 넓은 톱니 부분이 대가리다.**
- [확정, 사용자 2026-11-04] **부시와 너트도 넓은 지름 부분을 대가리라고 부른다**(볼트·T축의 머리와 같은 말).
- [확정, 사용자 2026-11-04] **부시와 너트는 대가리 부분이 바깥쪽이다.**
- **대가리가 모델 어느 쪽인가**(부품 모델 축은 부품마다 다르다 — 쓸 때는 이 표로 대가리 쪽을 찾는다):

| 부품 | 대가리 | 몸통 | 근거 |
|---|---|---|---|
| 부시 | −y (넓은 지름 쪽, 바깥) | +y (좁은 지름 쪽, 판 쪽) | `00_규칙.md` G5 |
| 너트 | −y (넓은 지름 쪽, 머리·턱) | +y (좁은 지름 쪽, 몸통 돌기) | G3, 연결점 `p1` 방향 +y |
| T축 | −y (둥근 접시) | +y (십자 끝, 꽂는 쪽) | 안내서 4-1, 연결점 `p1` 방향 +y |
| 8볼트·12볼트·서보고정볼트 | +y (머리) | −y (나사 돌기) | 연결점 `p1` 방향 −y(등록값, 눈으로 확인 전) |
| 스프라켓 | −y (넓은 톱니 부분) | +y (허브 관) | `00_규칙.md` G6 "돌기(+y 허브 관)"(등록값 `h1` 방향 −y, 눈으로 확인 전) |

- [가정 — 사용자 확인 전] 이름: **A면 = 몸통 쪽(판 구멍에 먼저 들어가는 면) / B면 = 대가리 쪽(바깥에 보이는 면).** 모델 축 부호는 위 표대로 부품마다 반대일 수 있다(볼트는 대가리가 +y). 연결점 구멍 번호에 A·B 를 붙이는 일은 아직 안 했다.
- [확정, 사용자 2026-11-04] **눈블록과 바퀴(작은바퀴·데코바퀴·중간바퀴)는 돌기가 분명해서 방향이 돌기로 정해진다 — 대가리 구분(A면·B면)을 따로 하지 않는다.**
- 이 밖에 양쪽이 다른 부품(서보혼 등)은 사용자가 정하면 여기에 추가한다 — 아직 정하지 않았다.

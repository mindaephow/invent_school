# 공통. 조립도를 만들 때마다 나아지게 하는 규칙

01~05 과정 어디에서든 적용한다.

1. **덮어쓰기:** 번호나 차시를 하다가 빈틈·실수를 발견하면 해당 과정 파일(01~05)의 그 자리를 덮어쓴다. 덧붙이지 않고, 옛 설명은 지운다.
2. **두 번 나온 실수는 자동 검사로:** 같은 종류의 실수가 두 번 나오면 문장으로 적지 않고 `stepchecks.py` 에 검사로 넣는다(예: 부시 방향 `bush_wrong`). 사용자 ✓ 번호는 막지 않는다.
3. **회귀 확인:** 검사나 규칙을 바꾸면 이미 만든 조립도 전부에 돌려 결과가 같은지(또는 틀린 것만 잡히는지) 확인한 뒤에 쓴다.
4. **차시 보고:** 차시가 끝나면 "어느 과정에서 무엇이 빠졌고 어느 파일의 어디를 고쳤는지"를 한 번 보고한다.
5. **사용자가 화면에서 고친 기록(❄·📷)이 가장 정확한 가르침이다:** 코드 값과 비교해 내가 반복해서 틀리는 부품 종류를 찾고(2026-10-12 분석: 자세를 고친 부품은 276건 중 10건 — 부시·리벳·메인보드·판 묶음), 그 종류는 검사나 방향 카드로 옮긴다. 차이는 두 파일로 따로 모아 둔다(`scripts/assembly-tools/user_diffs/`): **요청차이.md**(내 결정과 사용자가 말씀으로 바로잡은 것 — 바로잡으시면 한 항목 추가), **수정저장차이.md**(내 코드와 사용자가 화면에서 고쳐 저장한 ❄·📷 — `python collect_diffs.py` 로 DB 에서 다시 만든다). 카메라는 사용자가 번호마다 보기 좋게 정하므로 짐작(guess)으로 두지 말고, 값을 확정했다고 적을 때는 두 방향(예: X·Z)을 모두 확인한 경우에만 적는다.
6. **앞 과정이 끝나지 않으면 다음으로 넘어가지 않는다(2026-10-12):** 02 → 03 → 04 → 05 순서와 번호 순서는 `number_start.py` 가 막는다(끝나지 않은 앞 과정·앞 번호가 있으면 목록만 보여 주고 멈춘다). 안 한 게 있으면 보고하지 말고 그것부터 한다. 과정을 하나 더 만들면 그 완료 조건도 이 점검에 넣는다.
7. **규칙을 어기는 길은 도구가 막는다(2026-10-12 드롭체커):** 기준 미달을 만나면 멈추지 말고 05_조립 0-1 절의 순서(holefit 자동 DoG → infer_grid.py 로 정보를 모아 유추)로 푼다. 유추로도 가설이 하나로 안 갈릴 때만 멈추고 시도·수치·필요한 추가 근거를 보고한다 — 기준을 낮추는 옵션을 만들거나 손으로 만든 격자·추정 카메라로 지나가지 않는다. `python rulecheck.py <이름>` 이 번호마다 격자 출처(holefit 가 기준대로 만든 것인가)·카메라 오차(≤2px, 점 4개 이상)·증거·읽기 표를 판정해 ❌ 와 해결 명령을 보여 주고, `number_start.py` 는 앞 번호에 ❌ 가 있으면 다음 번호를 시작하지 못하게 한다. 예외는 사용자 말씀을 그대로 적은 `<이름>_approvals.json`(Claude 는 쓰지 않는다)뿐이다.
8. **지키기 쉬워야 규칙이다:** 번거로워서 어기게 되는 규칙은 도구가 대신 하게 하거나, 어기면 빌드가 막히게 한다. 둘 다 안 되는 규칙은 지운다.

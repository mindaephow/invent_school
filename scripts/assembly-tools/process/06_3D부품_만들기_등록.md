# 3D 부품 만들기·등록 규칙 (2026-10-30 정리)

조립도를 만들려면 부품 3D 모델·연결점이 DB 에 있어야 한다(`03_부품체크.md` A). 이 문서는 **부품 3D 를 새로 만들어 등록할 때** 흩어져 있던 규칙을 순서대로 모은 입구다.
숫자·규격은 원본에만 있다(아래 "원본" 표). 여기엔 순서·금지·확인 방법만 적고, 규격이 필요하면 원본을 연다. `문서지도.md` 원칙대로 같은 글을 두 곳에 두지 않는다.

## 1. 만들기 전

1. **규격 문서를 먼저 읽고** 첫 보고에 "이번 부품에서 지킬 규칙 3개"를 적는다. 큐보 전용이 아니다 — 에이스랩·주니어·프로보도 용량·검증은 같다(2026-10-27 곡면판 2.1MB·짝 없는 모서리 193개 사고).
2. **기존 생성기부터 읽는다.** 브랜드마다 `scripts/make-*.mjs` + `app/lib/*-mesh.js` 가 있다. 같은 방식으로 새 스크립트를 만들고, 내 방식으로 새로 짜지 않는다(2026-10-30 프로보 부품에서 읽지 않고 만들다 시간을 크게 잃었다).
3. **DB 에 이미 있는 행인지 이름으로 찾는다.** 부품 행(이름·권·수량)은 교재 등록 때 미리 만들어 두는 경우가 많고 3D 만 비어 있다. 새 행을 또 만들면 중복이 된다. (`ivs_part_catalog`, 이름은 `data->>name`; 브랜드는 `data.category` = `ivs_robot_categories`)
4. **교재 부품표·그림을 직접 본다.** 등록된 교재 PDF 로 대조한다(`CLAUDE.md` "책 대조"). 권별 "부품수량확인" 쪽에서 수량·모양을 읽고, 그 부품이 처음 나오는 권(신규)과 이어 쓰는 권(누적)을 가른다. PDF 글자가 깨져 글자 검색이 안 되면 쪽을 이미지로 렌더해서 읽는다. 책에 치수가 없으면 유추하되 **추정이라고 적는다**.
5. **"규칙이 없다"고 하지 않는다.** 기어·T축·눈블록 같은 새 모양도 기본 규격(구멍 구조·간격·두께)에서 유추해 먼저 만들어 보여 준다(`feedback_infer_parts_from_base_rules.md`).
6. 사용자가 숫자를 말하면 **오타일 수 있다**(8↔9 이웃 키: "38블록"=3X8, "18블럭"=1X8 8홀짜리). 이상하면 부품표 크기로 먼저 맞춰 본다. "유추해봐"는 되묻지 말고 계산으로 정하라는 뜻이다.

## 2. 만들 때 (공통)

- 구멍·돌기(끼우는 곳)는 그 브랜드의 규격 그대로. 몸통 모양은 자유지만 구멍·돌기를 막거나 간섭하면 안 된다.
- **자르기(CSG)로 큰 부품을 만들지 않는다.** 판·프레임류는 삼각형을 직접 짜서 몸통 2~3천 개·약 110KB 기준(큐보 35프레임 6,316개·308KB 비교). 작은 회전체·핀류는 manifold 로 자르기를 써도 되지만 용량·검사를 같은 기준으로 본다.
- 칸으로 나눈 면은 `conformTJunctions`, 곡면 마디 각도는 1° 미만, 구부린 부품은 구멍 중심 각도마다 윤곽에 점.
- **근거 없이 넣은 구조를 쓰지 않는다**(예: 책에 없는 끝 단차를 임의로 넣었다가 "두 부품을 합친 거냐" 지적 — 아치블럭 2026-10-30).
- STL 방향: 앱은 STL 을 읽을 때 `rotateX(-90°)` 하고 **x·z 가운데를 원점, 바닥 y=0**으로 옮긴다. 비대칭이면 미리 가운데를 맞추고, 눕혀서 만든다(사용자 "눕혀서 만들면 되잖아"). 색은 STL 에 없고 등록할 때 정한다.
- 등록된 색은 그대로 쓴다(강조·덧입히기 금지, `feedback_use_registered_colors.md`).
- 테두리 선(로버트론 부품): 실제 윤곽을 따라 0.1mm, 어두운 색은 밝게·밝은 색은 어둡게.
- 2D SVG 를 확인용으로 만들지 않는다. 3D 뷰어로 본다.

## 3. 만든 뒤 검증 (끝낸다고 말하기 전)

1. **숫자**: 삼각형 수·KB(몸통/선 따로)·짝 없는 모서리 0·같은 방향 겹침 0·부피 양수. `checkMesh`(`app/lib/cubo-mesh-repair.js`) 출력을 그대로 보고한다. 비슷한 부품과 같은 크기로 비교한다.
2. **치수 대조**: 사용자가 말한 값(가로·높이·구멍 간격·구멍 수)을 스크립트 출력으로 다시 잰다. 둘을 동시에 못 맞추면 어느 쪽을 택했는지 숫자로 말한다.
3. **결합 확인**: 다른 부품과 맞물리는 부품은 실제 짝(예: 1X8·3X8 블럭) 위에 겹쳐 구멍 위치가 맞는지 본다(겹침 없음 ≠ 정답, `feedback_check_direction_position_hole.md`).
4. **화면 확인**은 아래 4절. "화면에서 괜찮아 보임"만으로 끝내지 않는다.

## 4. 등록과 확인

**누가 어떤 길로 등록하나** — 쓰기는 공유 DB 수정이다. 아래 둘이 서로 다른 지시로 남아 있다(어느 쪽이 현재 유효한지 사용자에게 한 번 확인하면 좋다).
- 큐보 규칙: STL 을 만들어 파일 위치를 알려 주면 사용자가 부품 만들기에서 STL 가져오기로 직접 등록한다. `apply_part_to_db` 는 **사용자가 허락했을 때만**(`confirm: true`).
- 프로보 커넥트: `register-proboconnect-parts.mjs` 머리말에 "부품 등록은 알아서 하라"(사용자 2026-10-29)가 적혀 있다. 2026-10-30 에도 같은 스크립트로 등록해 막히지 않았다. 다른 브랜드·다른 부품에는 이 허락을 넓혀 쓰지 않는다.

**등록 길(셋 중 하나)**
1. 부품 수리실 → 도형 에디터/부품 만들기 → "새 부품으로 등록" 모달(과목·카테고리·권·수량 선택). 단순한 도형(기어·원통·블록)에 맞다.
2. 생성 스크립트 + 등록 스크립트(`register-proboconnect-parts.mjs <행 id> <STL> <크기> <색>`, 큐보는 `apply_part_to_db`). 등록 스크립트는 `thumbnail3d` 를 비운다.
3. 부품 관리 목록의 "수정"(이름·색·크기), "+ 다른 권에 등록"(권·수량만 추가).

**진행 방식(사용자 2026-10-30): 만들고 → 그 로봇의 부품 행에 바로 등록 → "✅ 골라서 그리기"로 그 부품 썸네일만 그림 → 그 부품 리스트에서 3D 창으로 보여 준다.** 등록 전에 따로 미리보기·오버레이·부품 수리실 화면을 띄우지 않는다. 검증은 숫자(3절)로 하고, 사용자가 겹쳐 보라고 했을 때만 부품 관리 화면에서 한다. 보고에는 "어느 로봇의 몇 권 행에 등록했는지"를 쓴다. **고칠 때도 같다** — 같은 행에 다시 등록하고 그 부품 리스트의 3D 창(이름·크기가 위에 뜨는 창)을 열어 둔 채로 보고한다.

**등록 직후(묻지 말고 바로)**
1. 브라우저 pane 새로고침 → **부품 관리 → 그 로봇 탭 → 권별 부품리스트**(또는 이름 검색칸)에서 그 행의 3D 창을 열어 눈으로 확인한다. (보여 주는 곳은 부품 관리다. 부품 수리실에 임시 화면을 띄우지 않는다 — `feedback_provo_parts_in_parts_screen.md`.)
2. 설계 화면은 `thumbnail3d` 가 있어야 3D 로 보인다(없으면 옛 SVG). 부품 관리 → "✅ 골라서 그리기"에서 **새 부품 id 만** 체크해 그린다. "전체 다시 그리기"는 다른 부품 썸네일까지 건드리니 쓰지 않는다.
3. 이름으로 찾을 때는 부품 관리 맨 위 **이름 검색칸**(2026-10-30 추가)을 쓴다. 권별 목록은 접혀 있다.
4. 센서·리모컨·모터는 **이름 규칙**을 지켜야 로봇별 요약 칸에 들어간다(이름에 "센서"/"리모컨"/"수신"/"모터", `project_robot_sensor_remote_summary.md`). 권(volumes)도 빠뜨리지 않는다.
5. 연결점(돌기·구멍 좌표)을 기록한다 — 조립도에 쓸 부품이면 `set_part_connectors`, 확인은 3D 뷰어의 🟢 연결점 버튼.
6. 임시로 `public/_*.stl` 같은 파일을 서버 폴더에 뒀다면 끝나고 지운다.
7. 커밋·푸시는 하지 않는다. 사용자가 "업로드"라고 말했을 때만.

**5-2. 큐보에서 특히 어긴 규칙**
- 블록 구멍은 **프레임 구멍과 같게**(등록된 2단·3단 블록의 안쪽 단은 서로 달랐다 — 사용자 결정). 판 두께 3 + 테두리 1×2 = 5. 돌기 길이 5 = 프레임 두께.
- 새 모양도 "규칙이 없다"고 하지 않는다. `get_part_standard`의 **부품 원칙** 5가지: 끼우는 곳은 규격 그대로 → 몸통은 자유(구멍·돌기 막지 말 것) → `compute_attach` 로 실제 끼워지는지 → 연결점 기록 → DB 쓰기는 허락 뒤.
- 호·곡선 부품은 구멍 중심 각도마다 윤곽에 점을 둔다(직선 조각이 구멍 테두리를 가로지르면 안 됨). 22.5° 같은 균등 간격은 틀린 값이었다(반원프레임).
- 팅커캐드에서도 열어 보게 한다(제 뷰어에서 괜찮아도 깨질 수 있음). 3D 뷰어는 앞면만 그려서 뒤집힌 면을 찾는다.
- 부품 등록 기록: 조립도에 쓰는 부품 52종 중 49종에 모델+연결점이 있다(고무밴드·3P 케이블·리모컨은 모델 없음 → 조립도 제외, `project_cubo_parts_status_1001.md`).

**5-3. 연결점(돌기·구멍) 기록** — 조립도에 쓸 부품이면 필수 (안내서 7장, `03_부품체크.md` A)
1. 새 부품을 등록하면 먼저 `measure_part(이름)` 으로 실측한다(크기, 대칭도, 둥근 돌기·구멍의 위치·반지름·방향, 등록 연결점과 ✓/△/✗/➕ 대조). 눈으로 세기 전에 먼저 부른다.
2. `set_part_connectors` 로 `{pegs:[{id,pos,dir,len,r}], holes:[{id,pos,dir,r,through}], note}` 를 기록한다(좌표 = 3D 모델 bbox 가운데 원점, y 위). 저장하면 이 부품을 쓰는 조립도를 전·후로 검사해 알려 준다 — 새 경고가 있으면 그 조립도를 `build.py <이름> --write` 로 다시 빌드한다.
3. 연결점은 **부품에 고정된 값**이다. 틀리면 단계 데이터가 아니라 부품 DB 를 고친다(`guideMode="mates"` 기본). 모델과 DB 설명이 다르면 바로 고친다(예: T축 접시는 −y 끝).
4. 십자(+)·네모 소켓·육각 축은 원통 탐지가 못 잡는다 — 그런 자리는 ✗ 가 나와도 정상이고 손으로 적는다. `confidence` 가 `checked` 면 믿고 `auto` 면 확인 후 쓴다.
5. 새 부품은 조립 프로그램에도 있어야 한다: `partlib.py` 의 `OTHER` 에 옮기고 `python partlib.py` 로 `conn.json`·`dims.json` 을 다시 만든다. 방향이 정해진 부품(메인보드·DC모터·바퀴·부시)은 면 사실(`measure_part`·`get_part_faces`)을 읽어 둔다. 확정된 면 메모는 안내서 "4-1. 부품 확정 메모".

**5-4. 출력용(프린트용) 모델은 따로다** — 조립도용 모델(`data.spec`)과 다르다. 섞지 않는다.
- 규격(사용자 2026-10-22~23): 노즐 0.4 PLA, 구멍 목 지름 6.10(조립도용 5.5), 입구 지름 7.7·깊이 1.1, 고리 벽 0.8, 목 두께 2.8, 총 두께 5, **눕혀서 출력**, 축·T축이 들어가는 열십자 구멍은 작은기어의 열십자 그대로, 구멍 목마다 홈 8곳(폭 0.8·깊이 0.3). 프레임 폭 10 은 그대로라 바깥 벽이 1−L 로 얇아진다(0.65 이상).
- 코드: `make-print-csg.mjs`(원래 디자인 + 불리언), `make-print-frames.mjs`(원 둘레 64분할, 20분할이면 각져 보임), `make-print-parts.mjs`·`make-print-notch-parts.mjs`(기타 부품), `make-print-test.mjs`·`make-print-rib.mjs`(시험 조각, 여유 L 0.15/0.25/0.35), `make-bent-wide.mjs`.
- 등록: `register-print-stl.mjs <STL 폴더>`(각 부품 행 `data.print` 에 gzip+base64, **`data.spec` 은 건드리지 않음**, 덮어쓰기 전 원래 행을 `DB백업/` 에 JSON 으로 저장), 꺼내기: `get-print-stl.mjs <이름|all>`. 부품 관리 목록의 "출력용 받기"·"출력용 받기(채움·홈8)" 버튼이 이 값을 쓴다. `update_part` 는 `print`·`printSkin` 을 지우지 않는다.
- 로버트론 출력용은 `make-robotron-print.mjs <junior|acelab> [--write]` (큐보용 `register-print-stl`/`get-print-stl` 은 이름으로 행을 찾아서 큐보·주니어 이름이 겹치면 못 쓴다).

## 6. 프로보 커넥트 (규칙이 저장소에 없던 곳 — 2026-10-30 확인한 것만)

- 생성기: `scripts/make-proboconnect-{block,pin,dualpin,steppin,hinge,gear,arch}.mjs`, 공통 `app/lib/proboconnect-block-mesh.js`(`PROBO_STD`, `toothPts`, `openPts`, `roundPoly`), 핀 `proboconnect-pin-mesh.js`. 블럭 두께 5·폭 10·구멍 간격 10, 구멍은 입구(반지름 3.95)+가운데 띠(턱)+아래 입구. `PROBO_STD` 의 ⚠ 표시 값은 **그림으로 읽은 추정**이다.
- 한 줄 블럭(1XN)의 맨 끝 구멍은 **톱니 입구**(스텝핀이 딸깍 걸리는 곳). 아치블럭은 1·5·9번이 톱니 홀.
- 색: 블럭 흰색 `#ffffff`, 2단핀 파랑 `#1e50b4`, 3단핀 노랑, 듀얼핀·아치블럭 빨강, 톱니블럭 회색 `#8c8c8c`(교재 그림 색 기준).
- 교재: DB `ivs_textbooks`(프로보 커넥트 1~6단계 PDF). 권마다 앞쪽 "부품수량확인"에 신규 수량, 뒤 권은 "1~N단계 부품 리스트"에 누적이 있다. 수량은 DB `volumes`(권별 신규 수량)로 맞춘다.
- 호·원 부품은 **구멍 개수·이웃 구멍 간격·바깥 크기**를 사용자 말과 대조한다. 현 길이(구멍 사이 직선)는 곧은 블럭(1X8=70, 1X9=80)의 끝 구멍 거리와 맞는지 본다. 3X8(80×30)·1X8 은 생성기로 임시로 만들어 겹쳐 본다(`make-proboconnect-block.mjs 8 파일 [줄 수]`).
- 부품 관리의 "겹쳐 보기"는 `window.__partsLabViewer.renderShapesPreview` 에 shape 두 개를 주고, 위에 얹을 쪽을 `paint:true`(색칠 조각)로 하면 따로 색이 보인다.

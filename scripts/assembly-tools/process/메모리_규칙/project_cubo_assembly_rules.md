설계 화면(design.html)의 "🧩 조립 보기"는 교재(2020년 큐보 1단계 PDF, 토끼 = 13~16쪽, **22단계**)를 단계별로 보여주는 기능. 데이터: `public/design-assemblies.js`(머리 주석에 필드 설명), 화면: `design-assembly.js`, 연결부: design.html의 `window.__ivsAssemblyBridge`. 2026-10-01 사용자와 1~22단계를 순서대로 다듬어 전부 올림(마지막 22번 화면은 사용자 확인 대기).

**조립 규칙(사용자가 알려준 것, 화면·안내서에 있음)**: 돌기 있는 부품의 돌기가 프레임 홀에 끼워진다 / 돌기를 화살표 방향으로 움직여 초록 표시 구멍에 삽입 / 홀에 돌기가 끼워지는 것 외엔 겹칠 수 없다 / 리벳도 돌기 역할(구멍 2곳 결합) / 브라켓은 다리(세로 판 밖). 새 규칙은 `IVS_ASSEMBLY_RULES`에 한 줄 추가.

**현재 배치(좌표 mm)**: 머리(벽·눈) −x, 뒤(막대·뒷다리) +x. 바닥 프레임 구멍 x=−15~35(6칸) z=−20~20(5줄). 3단블록 x=−5,5,15 줄 z=±20, 2단블록 x=25,35 줄 z=±10(바닥 앞쪽 끝). 벽=3단블록 머리쪽(−x) 끝 돌기. 덮개: 11번 3단 돌기(x=−5,5) → 12번 x=15(z±20)+x=25(z±10). 기어 묶음(T축+기어 / 15프레임+부시)은 2단블록 덮개 안 덮인 돌기 x=35(z±10)에(13·14 따로 조립, 15 합침). 16 뒤 막대=2단블록 끝 돌기(x=45), 17~20 앞다리(3단블록 옆 x=−5 구멍), 21 리벳→뒤 막대 양 끝, 22 2열브라켓 뒷다리.

**배운 점(사용자에게 여러 번 지적받음)**: 겹침 없음은 증거가 아님 → 새 부품 돌기↔구멍 결합 검사(`bridge.connectorsByName()` + design-mates.js, 콘솔에서 script 주입) + 확대 화면으로 방향·위치·홀·끼우는 방향을 단계마다 확인. 위치는 구멍 수로 센다("한 칸"=10mm). T축 접시 머리는 모델 −y 끝(DB 설명이 반대였어서 바로 고침) → 위로 오게 r=[180,0,0], 기어 윗면에 딱 얹힘. 부품 DB 설명 틀린 건 바로 고친다(update_part API는 로컬 서버가 500이라 배포 사이트에서 sessionStorage 토큰을 window.name으로 넘겨 호출). 교재가 "결합 전"을 펼쳐 그린 단계는 explode로. 카메라는 끼우는 곳을 보여준다(단계 `view`=90°단위, 3단계 1, 4~10 2, 19·20 −0.5).

**표시 방식(사용자 지시)**: 돌기 끝 초록 점 → 화살표(점에서 떨어뜨림) → 받는 구멍 초록 점(고리 금지, 면에 붙여 칠함, 얇은 판은 양면). 움직이는 부품 쪽 점은 부품에 붙어 따라다니고 화살표는 매 프레임 잇는다. X·Y·Z 방향선은 바닥 모눈에 얇게.

**조립 보기 화면 결정사항(사용자 지시, 2026-10-01)**: "조립 보기" 버튼 삭제(숫자·목록 클릭으로 열림) / 패널: 슬라이더→⏮◀▶⏭→역재생·재생→재생속도→볼륨→조립도 닫기→큐보 조립 방식 / 재생=화살표→결합 반복, 재생 중 초록 점 숨김, 결합 시 "딱" 소리(Web Audio) / 부품 창은 조립 보기 중 왼쪽 "부품" 목록 위에 붙고 삭제 버튼 없음·결합/원위치 있음 / 사용·필요 부품 숫자는 종류 수 / 바닥 +X −X +Z −Z +Y 방향선+정가운데 점(글씨 없음) / 작업 기록 패널 숨김. 데이터 새 필드: recv(marks=고정 돌기 끝), hover, pegDepth, thick, faceMarks, settleDir, explode, joinOrder, step.view. MCP 안내서(app/lib/cubo-assembly-guide.js §3·§9)와 validate_assembly(checkSteps, design-mates.js)에 반영 완료. 사용자가 "왜 그렇게 했냐"고 물으면 근거 없이 임의로 정한 것(예: 부품 숫자 단위)은 솔직히 인정하고 사용자 선호로 되돌린다.

**남은 것**: 부시(12mm)와 뒤 막대 1mm 겹침(카탈로그 치수, 교재도 거의 닿음). 나머지 1권 차시 조립도(부품 목록 등록된 건 준비/토끼/양팔저울). 3D 디자인 MCP, 무거운 3D 데이터 로컬 캐시(IndexedDB)는 미착수. "↺ 원위치" 버튼 삭제 여부 질문 미답.

**충돌 방지 범위/한계**: 몸통 상자(OBB)끼리만 검사 — 프레임·N단블록·브라켓·눈블록·기어·부시만 규칙 있음, 리벳·축 등은 검사 안 함. 연결점 DB: 1권 부품 30종 ivs_part_catalog.data.connectors(도구 public/connector-tools.js, MCP 큐보 조립 도구는 /api/mcp에 통합).

**Why:** 학생이 책의 평면 그림을 입체로 보게 하려는 목적. **How to apply:** 단계 위치를 고칠 때 이 규칙·실제 3D 모델 방향·결합 검사를 기준으로, 안 시킨 단계는 손대지 않는다. [[feedback_use_registered_colors]] [[feedback_check_direction_position_hole]]

**양팔저울(2차시) 1차 — 2026-10-01 올림(5155900)**: 교재 17~23쪽(PDF 쪽번호=교재 쪽번호), 26단계. 부품 수량은 교재 17쪽 LIST가 기준(2단블록 8·3단블록 10; 사이트 등록값 16/20은 2배로 잘못 등록됨→사용자가 고치기로). 1차에서 교재와 다르게 한 것: 탑을 세운 채로 만듦, 교재 2~3 병합, 교재 18 생략, 교재 9~11(반원프레임·눈블록 머리) 생략(교재 20 부시는 그림대로 넣음 — 사용자 원칙: 수량에 맞춰 조립도를 빼지 말고 조립도에 맞춰 등록 수량을 늘린다), 바구니 2개는 side 자리에서 만든 뒤 매닮. 만든 방법=연결점으로 돌기→구멍 자세 계산+결합검사로 안내 자동 추출. 사용자는 단계마다 사용 부품 수와 등록 수량 일치를 확인하길 원함. 이어서 사용자 단계별 검토·수정 예정.

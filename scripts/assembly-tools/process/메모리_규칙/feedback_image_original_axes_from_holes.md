**이미지 회전은 해도 되고 안 해도 된다(사용자 2026-10-14). 중요한 건 조립도를 잘 그리기 위한 문제 해결이다.** 회전 방식(`rotate_to` 작은 각도 회전, `level` 수평 맞추기, `no_rotate` 안 돌림)은 모두 쓸 수 있는 선택지이고, 그림마다 구멍 줄과 축선이 실제로 맞아 보이는 쪽을 고른다. 특정 방식을 금지하는 규칙으로 만들지 않는다.

가장 중요한 순서(사용자 2026-10-13): **홀라인을 맞춰서 규칙대로 이미지 작업 → 방향 판단 → 작업공간에 올림.** 축·카메라는 구멍 점 PnP(`axes_fit.py`), 회전하면 `refs_rect` 가 보고하는 회전 각도·구멍 줄↔축선 각도 차(°)로 확인한다.

**Why:** 그림을 수평으로 돌렸더니 축선(원래 방향)과 구멍 줄이 어긋나 "맞는 게 하나도 없다"는 지적(드롭체커 24번)은 그 그림에서 그 방식이 안 맞았다는 사례이지 수평 맞추기 금지가 아니다. PnP 축선을 그리면 구멍 줄과 나란했고(차이 1.8°·3.6°) 사용자가 "잘했네, 이 방식으로 등록"이라 했다. 2026-10-14 사용자가 "회전해도 되고 안 해도 된다"고 바로잡음 — 앞서 내가 "수평 맞추기 금지·level 삭제 대상"으로 정리한 것은 잘못이었다.

**How to apply:** 구멍 점(holefit; 기본 방식이 기준 미달이면 DoG 방식이 자동으로 이어짐, 막히면 `infer_grid.py`) → axes_fit → refs_rect(회전 각도·각도 차 보고) → NN_2 눈 확인 → DB 업로드 → 방향 판단 → 놓기. 회전 옵션을 지우거나 막으라는 요청이 아니므로 `level`·`no_rotate`·`rotate_to` 코드는 그대로 둔다(2026-10-14 확인: 모두 `refs_rect.py` 에 살아 있고, `level` 은 투석기 18·20·21·23번 `_axes.json` 4개, `no_rotate` 는 투석기 12개·드롭체커 26개가 쓴다). 문서에 "수정되었다" 이력을 남기지 않는다.

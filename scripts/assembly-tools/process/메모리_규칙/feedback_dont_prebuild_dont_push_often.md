요청받지 않은 일을 "테스트 겸" 미리 하지 않는다(예: 교재 큐보 1권 전체 쪽 이미지를 Supabase 저장소에 미리 업로드 — 쪽 이미지는 조립도를 그릴 때 필요한 쪽만 올린다). GitHub 푸시는 사용자가 말했을 때만, 도구 하나 끝날 때마다 올리지 말고 모아서 한 번에 한다.

**Why:** 2026-10-03 하루에 푸시를 10번 해서 Vercel 배포·빌드 제한(예전에 24시간 제한에 걸린 적 있음)에 부담을 줬고, 사용자가 "업로드를 너무 자주 하지 마"라고 지적. 교재 쪽 이미지 미리 올리기도 "왜 네가 먼저 하냐"고 지적받음. 또 연결점 표시를 말없이 끄거나, 스크린샷에 보인 MCP 키로 쓰기 작업(데코바퀴 복구, 쪽 이미지 업로드)을 한 것도 밝혀야 했다.

2026-10-06 배틀로봇 19·20번 작은기어 작업 중 ❄ 모습 기록(ivs_assembly_poses)이 로컬 데이터를 덮는다는 걸 찾고 DB 행을 직접 고치려 upsert 를 시도(오류로 막혀 변경 없음) → 사용자가 "로컬을 수정해", "왜 시키지 않은 업로드를 자꾸 해, 규칙 안 봤어?"라고 지적. DB 쓰기도 업로드다 — 고치라는 말이 없으면 시도 자체를 하지 않는다. 로컬로 푸는 방법: 부품에 noFreeze: [단계들] 를 달면(design-assembly.js 가 그 단계의 ❄ 기록을 무시) 로컬 데이터가 이긴다.

**How to apply:** 변경은 로컬에서 시험하고 모아 두었다가 "올릴까요?" 한 번에 묻는다(배포를 거쳐야 확인되는 MCP 도구 등). Supabase 저장소/DB 쓰기는 요청 범위 안에서만. 보이는 설정(연결점 표시 등)을 바꾸면 알리고 되돌린다. 안내서(cubo-assembly-guide.js)는 통째로 템플릿 문자열이라 백틱·달러+중괄호를 쓰면 빌드가 깨진다 — 검사는 node --check 가 아니라 import 로 한다. 관련: [[feedback-no-unilateral-action]].

2026-10-01 사용자와 확정. 프레임·블록 STL을 자르기(CSG) 없이 삼각형으로 직접 짜서 팅커캐드 STL 수준(2~3천 삼각형, ~110KB)으로 만든다. **규격 숫자의 원본은 `app/lib/cubo-part-maker.js`(CUBO_FRAME_STD, CUBO_BLOCK_STD, PART_STANDARD_TEXT)**, MCP `get_part_standard`로도 읽힌다.

**요약**: 구멍 = 입구 반지름 3.5(깊이 1) → 가장 좁은 곳 2.75, 간격 10. 프레임: 판 3 + 위아래 구멍 테두리(높이 1, 바깥 4/안 3.5) + 판 둘레 테두리(폭 1·높이 1) = 두께 5, 폭 10, 여백 5. 블록: 몸통 10×10×(10×칸), 구멍은 프레임과 같게, 앞뒤 칸마다·양 끝에 스냅핏 돌기(길이 5, 밑동 1mm r3.8, 몸통 r3.0, 끝 r2.5, 십자 홈 폭 1.2).

브라켓(1열·2열 ㄴ자)은 프레임과 같은 판 두 장: 바닥 팔 30(모서리 칸은 구멍 없음, 구멍 z 0·10), 세운 팔 높이 1열 30(구멍 y15·25)/2열 25(y10·20), 폭 10×열 수. 사용자 말: "구멍·간격·두께가 모두 규격이니, 모양이 불확실하면 3D로 만들어 보여 주고 고치면 된다". 판 생성기 `cubo-plate-mesh.js`가 프레임·브라켓 공용.

**사용**: `node scripts/make-part-stl.mjs frame 5 "C:/Users/user/Downloads/15프레임_규격.stl"` (block 3 = 3단블록). 파일을 사용자 다운로드 폴더에 두면 사용자가 부품 만들기에서 STL 가져오기로 직접 등록한다. 색은 STL에 없으니 등록 때 정한다. 부품 DB 직접 수정(MCP `apply_part_to_db`)은 사용자 허락 후에만.

**부품 원칙 (사용자가 명시하라고 함, 2026-10-01)**: 큐보 로봇은 부품끼리 블록·리벳에 끼워 조립하므로 ① 끼우는 곳(구멍·돌기)은 항상 규격 그대로(구멍 입구 r3.5 깊이1 → 최소 r2.75, 스냅핏 돌기 r3.0·십자홈 1.2, 리벳 r3.2가 걸림), 10mm 격자·간격 10, 판 두께 3·테두리 1. ② 그 외 몸통 모양(기어 이빨, T자, 눈 등)은 자유롭게 설계하되 구멍·돌기를 막거나 간섭하면 안 됨. ③ 만든 뒤 compute_attach로 기존 블록·리벳과 실제로 끼워지는지, 구멍 수·위치·면 방향을 직접 검사. ④ 연결점(돌기·구멍 좌표) 기록. ⑤ DB 쓰기는 허락 후에만.

**Why:** 사용자가 "메모리 없는 클로드도 언제든 만들 수 있어야 해"라고 요청. DB에 숫자로만 저장하면(CSG) 쓸 때 15초·삼각형 11배라 STL 직접 생성으로 정했다. 사용자는 한 번 만들어 확인한 뒤 직접 등록하는 흐름을 선택했다(자꾸 저장하지 말라고 함).
**How to apply:** 새 프레임·블록 요청이 오면 get_part_standard 또는 위 파일을 읽고 같은 방식으로 만든다. 브라켓·기어·T축·눈블록 등 다른 모양도 "규칙 없음"이라 하지 말고 아래 **부품 원칙**으로 유추해 먼저 만들어 보여 준다([[feedback-infer-parts-from-base-rules]]). 만든 뒤 화면(부품 만들기 미리보기)에서 사용자가 눈으로 보게 한다. 구멍 둘레가 뚫려 보이면 면 방향 뒤집힘(모서리 방향 검사)을 의심한다.

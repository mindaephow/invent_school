# 큐보 조립도 작업 — 입구 (규칙 원본은 `00_규칙.md`)

**조립도(조립 보기) 작업은 이 순서로 시작한다.** 이 파일은 입구이고, 규칙 문장은 한 곳에만 있다.

1. **`scripts/assembly-tools/process/00_규칙.md` 를 처음부터 읽는다.** 맨 위 "00. 조립도를 시작할 때"(03 부품 정리·04 창고 정리를 "1차"로 모든 번호에 먼저 끝낸 뒤 조립 — 대략 훑어 모든 번호를 기록하면 되고 정정은 조립 중에)와 "0. 번호 하나 체크리스트"(1쪽)가 번호마다 읽는 부분이고, 그 아래 A~J 가 주제별 규칙이다.
2. 읽은 뒤 첫 보고에 **"이번 번호에서 지킬 규칙 3개"**를 적고, `python number_start.py <이름> <번호>` 부터 돌린다(서버·로그인·`.env.local` 은 저장소 `CLAUDE.md` 시작 절).
3. 실행 순서·코드 템플릿·도구 사용법은 `process/05_조립.md`, 조립도별 진행 상태는 `process/인수인계_진행기록_<이름>.md`, 사용자가 말로 바로잡은 사례는 `user_diffs/요청차이.md`, 화면 조작 코드는 `process/viewer_snippets.md`.

**가장 중요한 원칙 (`00_규칙.md` 에 규칙 번호로 있다)**
- 조립도는 **결합되는 부분을 찾을 때까지 책(이번·앞·뒤 번호·완성 사진)을 확대해 관찰**해서 만든다(B5·H1).
- **문제가 생기면 멈추지 않는다** — 먼저 규칙을 순서대로 지켰는지 확인하고(증거 = DB 에 이미지 작업이 다 올라가 화면에 보이는 것), 그다음 무엇이 문제인지 자기에게 묻고 해답을 찾을 때까지 책을 뒤진다(B5·B6).
- **홀라인(구멍 격자)이 첫 단추**, 결합하는 쪽·되는 쪽 양쪽(D1·D2). 축·카메라는 격자에서 `axes_fit` 로 계산(E1).
- **그림은 만들자마자 DB 에 올린다.** 올리지 않은 채 멈추거나 넘어가지 않는다(I1).
- 수정할 때마다 화면을 새로 불러와 **6방향**으로 크게 본다(H2·J2). "도구 ✅"·"비슷하다"는 관찰이 아니다(H1).
- 사용자가 지정한 ❄·📷·✓ 가 무조건 우선(B3). ✓ 한 번호는 바꾸지 않고 ✓ 버튼은 누르지 않는다(C1·C2). 푸시는 사용자가 "업로드"라고 할 때만(I2).

옛 문장은 두지 않는다 — 규칙은 `00_규칙.md` 한 곳이다.

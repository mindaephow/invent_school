# 3D 부품 만들기·등록 (사용자 지시 2026-10-30: "3D 부품 등록할 거야" 하면 준비된 상태로 진행)

사용자는 큐보 → 에이스랩·로보타미주니어 → 프로보 커넥트 순서로 같은 흐름으로 부품을 만들어 왔다. **새 부품이든 고치는 것이든, 이미 있는 흐름(생성기·등록 스크립트·점검)을 먼저 읽고 같은 방식으로 한다.** 내 방식으로 새로 짜지 않는다 — 2026-10-30 프로보 부품에서 읽지 않고 만들다 오래 헤맸다.

## 맨 먼저 (2분)
1. `node scripts/part-start.mjs <부품이름>` — 개발 서버·.env·DB 읽기·브랜드별 현황·그 부품의 DB 행(모델/연결점/썸네일/출력용)·그 브랜드 생성기 목록·체크리스트를 한 번에 보여 준다. 이름이 모호하면 이름 없이도 돌려 현황만 본다.
2. 로그인 화면이면 사용자에게 로그인만 요청한다(비밀번호는 대신 입력하지 않는다). 개발 서버 주소·켜는 법은 저장소 `CLAUDE.md` 1번.
3. `scripts/assembly-tools/process/06_3D부품_만들기_등록.md` 를 읽는다(원본 위치 표 → 만들기 전 → 만들 때 → 검증 → 등록·확인 → 브랜드별 절). 규격 숫자는 `get_part_standard` 가 원본이다.
4. 첫 보고에 **"이번 부품에서 지킬 규칙 3개"** 를 적고 시작한다.

## 진행 방식 (사용자 지시 2026-10-30) — 만들고 → 그 로봇의 부품 리스트에 등록 → 썸네일 골라서 그리기 → 거기서 보여 준다
1. 모델을 만든다(스크립트 + 숫자 검증: 삼각형·KB·짝 없는 모서리 0·겹침 0·부피, 사용자 치수 재측정).
2. **해당 로봇(브랜드)의 부품 행에 바로 등록한다.** 등록 전에 따로 미리보기·오버레이·부품 수리실 화면을 띄우지 않는다(검증은 숫자로 하고, 사용자가 겹쳐 보라고 했을 때만 부품 관리 화면에서 한다).
3. **부품 관리의 "✅ 골라서 그리기"로 방금 등록·수정한 부품 id 만 골라 3D 썸네일을 그린다**(전체 다시 그리기는 다른 부품 썸네일까지 건드리니 쓰지 않는다. 등록 스크립트가 썸네일을 비우기 때문에 이 단계가 꼭 필요하다).
4. **그다음 부품 관리 → 그 로봇 탭 → 권별 부품리스트에서 그 부품의 3D 창을 열어 보여 준다**(이름 검색칸으로 찾아도 된다). 보고에는 어느 로봇·몇 권 행에 등록했는지 쓴다.
5. 연결점(`measure_part` → `set_part_connectors`, 조립도에 쓸 부품이면 필수)까지 해야 끝이다.
6. 고치라고 하면 같은 행에 다시 등록하고 썸네일 골라서 그리기까지 한 뒤, 같은 부품 리스트에서 **3D 창(부품 이름·크기가 위에 뜨는 창)을 다시 열어 열어 둔 채로** 보고한다(2026-10-30 사용자 "수정할 때도 이렇게 열어서 보여주면 되는 거야"). 커밋·푸시는 "업로드"라고 할 때만.
등록 권한은 아래 "사용자가 반복해서 화낸 것"의 마지막 줄을 따른다.

## 사용자가 반복해서 화낸 것 (어기지 않는다)
- 기존 생성기를 안 읽고 새로 만든다 / 근거 없이 구조를 넣는다(아치블럭 끝 단차).
- 부품 수리실에 임시 화면을 띄워 보여 준다(보여 주는 곳은 부품 관리).
- 질문으로 되묻는다 — 틀렸다고 하면 묻지 말고 고치고 숫자로 보고한다. 단순한 질문엔 답만 한다.
- 사용자 숫자를 글자 그대로 읽는다 — 8↔9 오타가 잦다(38블록=3X8, 18블럭=1X8). "유추해봐"는 계산으로 정하라는 뜻.
- "규칙이 없다"고 말한다 — 기본 규격에서 유추해 먼저 만들어 보여 준다.
- 등록 허락: 큐보는 "DB 쓰기는 허락 뒤"(`apply_part_to_db confirm`), 프로보 커넥트는 "등록은 알아서"(2026-10-29, `register-proboconnect-parts.mjs`). 다른 브랜드로 넓혀 쓰지 않는다.

새로 배운 규칙은 `06_3D부품_만들기_등록.md` 의 해당 절에 적는다(메모리에만 적지 않는다).

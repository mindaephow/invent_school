# 조립검사 (조립도 자체: 결합·겹침·틈·방향·바닥)

규칙은 `scripts/assembly-tools/process/큐보 부품결합규칙.md` 의 "검사 지도"와 제2부(G 와 K0~K4). 교재 대조는 보지 않는다(그것은 textbook-check).

사용: `조립검사 <조립도이름> [번호…]` — 이름은 스크립트 이름(`balance` 등). 이름이 없으면 한 줄로 묻는다. 번호를 안 주면 전체.

**시작 전(시험·실전 똑같이, 건너뛰지 않는다):** ① `cd scripts/assembly-tools && PYTHONIOENCODING=utf-8 python session_start.py --아이디 <내 계정>` 으로 GitHub 최신본을 받고 로컬이 최신인지 본다(조립도 `.py` 가 최신본이어야 한다) ② `process/큐보 부품결합규칙.md` 를 처음부터 읽고 첫 보고에 '이번에 지킬 규칙 3개'를 적는다 ③ 그 뒤에 아래 점검을 돌린다.

`scripts/assembly-tools` 에서 `PYTHONIOENCODING=utf-8` 로 아래를 돌린다(둘 다 읽기만 한다).
1. `python cubo_joint_check.py <이름> [번호…]` — K1 규칙 2·3·5~10·13~15(리벳 틈, 프레임 겹침, 돌기 한 장, 방향 있는 부품, 볼트·너트).
2. `python joincheck.py <이름> [번호…]` — 리벳 틈, 볼트·너트가 구멍에 묻힘, 돌기 충돌.
3. **화살표(G1·G12):** 번호마다 `python matecheck.py <이름> <번호>` 를 전 번호(번호를 줬으면 그 번호) 돌려 끝줄 "맞물리지 않는 안내점 N개"를 모은다. 0개가 아니면 그 번호의 어긋난 안내점을 적는다. 부품이 없는 번호(`❌ …번에 부품이 없다`)는 건너뜀이 아니라 "부품 없음"으로 적는다. 결합 전 모습 규칙(리벳·T축·부시·볼트·너트는 띄워서 화살표, `seated` 금지, 화살표 수 = 돌기 수)도 이 단계에서 본다.
4. **부품 방향:** `runpy.run_path("<이름>.py", run_name="probe")` 로 읽은 뒤 `asmlib.orient_report(A)` — 단계의 부품마다 구멍 면·돌기 면이 세계 어느 쪽을 보는지 표로 나온다(`python <이름>.py --orient` 는 `_asm.json` 을 덮어쓰니 쓰지 않는다). 이 표를 책과 나란히 맞추는 것은 교재검사 몫이므로 방향 값만 보고한다.
5. **연결점(K3):** 부품마다 `check_chapter_parts(권, 차시)` 로 `confidence` 가 `checked` 인지(`auto`·없음은 확인 필요), 필요하면 `get_part_connectors` 와 `conn.json` 의 구멍·돌기 id 가 같은지 본다. 권·차시를 모르면 한 줄로 묻는다.
6. 기울어진 결합만 `python tiltjoin.py <이름> <번호>`.

보고할 때 지킬 것
- 출력의 줄 수가 아니라 **몇 단계를 점검했는지**와 `건너뜀`·`점검 오류` 줄이 없는지를 같이 확인한다(0건이어도 안 돌았을 수 있다).
- 화살표·부품 방향·연결점 결과도 같은 조립검사 보고에 번호별로 넣는다(위반 / 안내 / 못 한 것으로 나눠서).
- 도구가 재지 않는 항목(K1 의 1·4·12번, [미정])은 "점검 안 됨"으로 따로 적는다.
- 로컬 `<이름>.py` 기준이라 DB 에 올라간 최신본과 다를 수 있음을 한 줄 적는다.
- 교재 대조 결과(카메라·LIST 등)는 이 보고에 섞지 않는다. 고치라고 하지 않으면 고치지 않는다.
